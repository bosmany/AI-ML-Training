Ch 6: Professional Python

Compiled from the chapter text on 2026-09-21. A study aid: the lesson has the explanations and the caveats.

In short

  • 6.1 Virtual environments and pip. A venv is a private folder with its own Python and its own site-packages shelf. Activate it, pip install into it, and share a requirements.txt shopping list.
  • 6.2 Custom exceptions. Give each kind of failure its own class (class Name(Exception)). Group them under a base class, catch the specific one first, and never hide bugs behind a broad except Exception.
  • 6.3 and 6.4 Context managers. with guarantees cleanup. Build your own with @contextmanager (code before yield is setup, code after, inside finally, is cleanup) or with a class that has __enter__ and __exit__.
  • 6.5 to 6.9 Decorators. Functions are values, closures remember, so a decorator is a function that takes a function and returns a wrapper. @name means f = name(f), once, at definition time. Add @wraps(func).
  • 6.10 and 6.11 Generators. yield pauses a function and hands out one value at a time, so big data fits in memory. Chain generators into pipelines and use (x for x in data) for the lazy one-liner. A generator is used up after one pass.
  • 6.12 and 6.13 Logging. Levels (DEBUG, INFO, WARNING, ERROR, CRITICAL) plus a threshold replace scattered prints. Loggers create messages, handlers choose the destination, formatters choose the look.
  • 6.14 and 6.15 Testing. A test states an expected result. unittest (a TestCase class with test_... methods) ships with Python; pytest uses plain assert, fixtures and parametrize.
  • 6.16 pyproject.toml. One file describes the project: name, version, dependencies, command-line entry points and build tool.

Key ideas by section

Virtual Environments and pip: One Toolbox Per Project

  • A package is shared code; pip installs it; without isolation two projects can demand different versions of one name.
  • A virtual environment is a folder (.venv) with its own Python and its own site-packages shelf.
  • Activating only puts .venv/bin first on your search path, so python and pip mean this project's copies.

Custom Exceptions: Errors That Have a Name

  • An exception's type should say what went wrong; define your own with class Name(Exception): pass.
  • Group related errors under one base class: except Parent catches every child too.
  • Put the most specific except first; Python uses the first one that matches.

Context Managers: Cleanup That Cannot Be Forgotten

  • Cleanup that sits after risky code is skipped when an error jumps out; try / finally guarantees it.
  • A context manager bundles setup and cleanup; the with statement runs both for you.
  • With @contextmanager, code above the single yield is the entrance, code below it (inside finally) is the exit.

Class-Based Context Managers: __enter__ and __exit__

  • A class with __enter__ and __exit__ works after with; __enter__'s return value is what as names.
  • __exit__(self, exc_type, exc_value, traceback) always runs; all three are None when there was no error.
  • Return True from __exit__ to swallow an error, False to let it continue. Swallow only errors you understand.

Decorators, Step 1: Functions Are Values

  • def creates a function object; the name is only a label. f refers to it, f() runs it.
  • A function can be passed to another function and returned from one.
  • These are the two ingredients of a decorator: something that takes a function, and something that hands a function back.

Decorators, Step 2: Closures, Functions That Remember

  • An inner function can use variables from the function around it.
  • Python keeps those variables alive in a closure (a backpack) attached to the inner function.

Decorators, Step 3: Your First Decorator

  • A decorator is a function that takes a function and returns a wrapper function; @name above a def means f = name(f).
  • Decoration time happens once, when the def is read. Call time happens on every call and goes through the wrapper.

Decorators, Step 4: functools.wraps and Stacking

  • Without help, a decorated function's __name__ and __doc__ become those of wrapper.
  • Put @wraps(func) (from functools) on the wrapper to copy the original's identity; __wrapped__ reaches the original.

Decorators, Step 5: Decorators That Take Settings

  • @name(args) first calls name(args), then applies whatever it returns to the function below.
  • A decorator with settings needs three layers: factory (setting), decorator (function), wrapper (call).

Generators: Producing Values One at a Time

  • A generator function contains yield; calling it returns a generator object and runs nothing yet.
  • yield hands out a value and pauses the function; the next next() resumes right after it.

Generators in Practice: Pipelines and Generator Expressions

  • A generator can filter and repair as it goes: yield for good items, try/except around the bad ones.
  • Chained generators form a pipeline: one item moves through every stage before the next begins.

Logging, Part 1: print() That Grows Up

  • A level says how important a message is: DEBUG 10, INFO 20, WARNING 30, ERROR 40, CRITICAL 50.
  • The threshold (level= in basicConfig) hides everything below it, with no code edited.

Logging, Part 2: Loggers, Handlers and Formatters

  • A logger creates messages, a handler sends them to a destination, a formatter lays out the line.
  • A message must pass the logger's level, then each handler's level, so use handlers to split audiences.

Testing, Part 1: unittest, a Safety Net for Your Code

  • An automated test states an expected result; it catches broken behaviour the moment you change code.
  • With unittest, a class inherits TestCase, each test_... method makes checks such as assertEqual, assertTrue, assertRaises.

Testing, Part 2: pytest (Reference)

  • pytest finds test_*.py files and test_* functions on its own; the check is a plain assert.
  • Failures show the actual values, so you rarely need special assert methods.

pyproject.toml: The ID Card of a Project

  • pyproject.toml is the single ID card of a Python project: name, version, dependencies, commands, build tool.
  • TOML is a settings format that maps to dictionaries; tomllib reads it.

Watch out

  • Never call unittest.main() in this consoleunittest.main() ends by calling sys.exit(), which raises SystemExit and looks like a crash here. Use TextTestRunner(...).run(...) as in these examples.
