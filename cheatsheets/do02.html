DevOps 2: Config & Data Formats

Compiled from the chapter text on 2026-09-21. A study aid: the lesson has the explanations and the caveats.

In short

  • Parse safely: always yaml.safe_load (the full loader executes code named in the document); use safe_load_all for --- multi-document files and filter the empty trailing document.
  • Know the YAML 1.1 traps: NO/yes/off become booleans, 1.10 becomes 1.1, 22:22 becomes the base-60 integer 1342, 010 becomes octal 8, and dates aren't strings. Quote anything that must stay a string.
  • Choose the format on purpose: JSON for machines, YAML for human-written infra (with care), TOML for tool config (strict, no coercion), .env for per-deploy values that are always strings.
  • Layer config predictably: defaults < file < environment < CLI flags, coerce env strings to real types (bool("false") is True), and record which layer supplied each value.
  • Validate at startup with Pydantic: report every problem at once, use SecretStr, and redact anything you log — fail fast instead of failing at 3 a.m.
  • Drift detection = normalize, then diff: strip volatile fields, then compare desired and live recursively; kubectl diff and terraform plan are this idea at scale.
  • Write small policy gates in Python: lint manifests and gate Terraform plans, and exit non-zero on violations because CI only understands exit codes.

Key ideas by section

What Is Configuration, and Why Does It Live Outside the Code?

  • Configuration is the set of values a program reads that you can change without changing its logic.
  • Hard-coded values force a code edit per environment, and hard-coded passwords end up in git.
  • Good code receives its settings as data (a parameter), and the settings live in a config file, environment variables, or a secret manager.

JSON from Zero: Text That Becomes Dictionaries and Lists

  • JSON is plain text with six value kinds that map to dict, list, str, int/float, bool and None.
  • loads and dumps work on strings; load and dump work on files.
  • JSON is strict: double quotes only, no comments, no trailing commas. Errors quote the position.

Reaching Into Nested Data Without Crashing

  • Nested data is read by following a path: a key for each dict, a position for each list.
  • Square brackets raise KeyError when a step is missing; .get(key, default) returns the default instead.
  • In a chain, give every intermediate .get a {} default, or you get 'NoneType' object has no attribute 'get'.

Stable Output: Using dumps to Make Config Diffable and Hashable

  • Equal dictionaries can produce different JSON text, because key order follows insertion order.
  • A canonical form writes equal data as identical text: sort_keys=True, plus fixed separators for hashing.
  • Sorted, indented output makes diffs show only real changes; a hash of the canonical text detects any change at all.

YAML with PyYAML: safe_load, Multi-Document Streams, Anchors

  • In Python that means PyYAML (import yaml).
  • The single most important rule: always use yaml.safe_load, never a bare yaml.load.
  • Kubernetes tooling emits several documents in one file separated by ---, and docker-compose uses anchors (&name), aliases (*name) and the merge key (<<) to avoid repeating settings. safe_load_all returns one object per document…

YAML Gotchas: Type Coercion, the Norway Problem, and Base-60 Ports

  • YAML doesn't need quotes around strings, so the parser guesses a type for every bare word.
  • PyYAML implements YAML 1.1, whose guesses are surprising.

TOML with tomllib: Strict, Typed, and Boring (Good)

  • It is deliberately read-only (write with the third-party tomli_w), and it is strict: types are explicit (strings must be quoted, dates and datetimes are first-class), so there is no Norway problem — an unquoted NO is a syntax error, not a silent boolean.
  • TOML is what pyproject.toml uses, and it's a popular choice for tool configuration (Ruff, Black, pytest, Poetry, Hugo).
  • Python 3.11+ ships a reader in the standard library: tomllib.

.env Files and the Config Layering Rule

  • In practice you end up with several sources at once, and the essential engineering decision is a clear precedence order.
  • The near-universal convention is defaults < config file < environment variables < command-line flags: the more explicit and more temporary a source is, the higher it ranks.
  • The twelve-factor app rule says configuration that varies between deploys (hostnames, credentials, feature toggles) belongs in the environment, not in code.

Validating Config with Pydantic (and Never Logging Secrets)

  • Whether workers is a positive integer, whether port is in range, whether a required database host is present — that's validation, and doing it once, at startup is one of the highest-value habits in operations.
  • Parsing a config file only tells you it is syntactically valid.
  • Plain dicts leak: logging.info(config_dict) is one of the most common ways a password ends up in a log aggregator.

Deep-Diffing Configs: The Heart of Drift Detection

  • Every drift tool — kubectl diff, terraform plan, ArgoCD's "OutOfSync" — is the same algorithm at heart: compare a desired document with a live one and report what was added, removed, or changed.
  • Real objects carry volatile fields that always differ and have nothing to do with intent: Kubernetes adds status, metadata.resourceVersion, creationTimestamp and a uid to everything it stores.
  • Configuration drift is when what is running no longer matches what you declared: someone scaled a deployment by hand, an emergency hotfix never made it back to git, a console click changed a security group.

Linting Real Infrastructure YAML: Kubernetes Manifests

  • The most valuable use of everything above is policy checks before deploy: parse a manifest, apply rules, fail the pipeline on violations.
  • A Deployment nests its containers under spec.template.spec.containers, so the linter is mostly careful navigation with safe defaults.

Reading Terraform Plan JSON: Summarize Changes and Gate Dangerous Ones

  • Its resource_changes array lists every resource with change.actions: ["create"], ["update"], ["delete"], ["no-op"] — and a replacement appears as ["delete","create"] (destroy then recreate).
  • terraform plan can emit a machine-readable plan (terraform show -json).

Watch out

  • Quiet JSON traps. Duplicate keys are silently accepted and the last one wins: json.loads('{"a": 1, "a": 2}') gives {'a': 2}.
  • This is not theoretical. Config files arrive from pull requests, Helm charts pulled from the internet, and CI artifacts.
