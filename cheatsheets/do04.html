DevOps 4: Cloud & Container Ops by Example

Compiled from the chapter text on 2026-09-21. A study aid: the lesson has the explanations and the caveats.

In short

  • Handle the response, not just the call — missing keys (Tags), nesting (Reservations → Instances), pagination and units are where scripts break.
  • Always paginate, ideally with a paginator, and filter server-side. Ignoring it fails silently.
  • Audit the sneaky cases: IPv6, port ranges, protocol -1, single-value-or-list IAM fields, NotAction.
  • Triage pods by symptom: phase is coarse; the answer is in containerStatuses and conditions.
  • Requests schedule, limits enforce: CPU over limit is throttled, memory over limit is OOMKilled. 1G ≠ 1Gi.
  • Retry only what is transient, with backoff and jitter, and make retried writes idempotent.

Key ideas by section

The Cloud, an API and an SDK, in Plain Words

  • The cloud is rented computers you control by sending messages over the internet.
  • An API is the fixed menu of requests a service accepts, plus the shape of each response. Requests and responses are JSON, which maps to Python dicts and lists.
  • An SDK is a library that turns a Python method call into a request and the reply back into a dict.

boto3: Clients, Credentials and Regions

  • Credentials prove who you are; the SDK searches a fixed list of places (code, environment, config file, the server's role) and uses the first hit.
  • A region is one geographic cluster; resources exist in exactly one, and the wrong region returns an empty result, not an error.
  • A client is one method per API action, dicts in and dicts out. Prefer it over the resource wrapper.

Reading a Response Step by Step

  • Every response is dicts, lists and leaf values; every path is a chain of key lookups and positions.
  • Walk one hop at a time and print type(x) to see whether you hold a dict (need a key) or a list (need a position or a loop).
  • KeyError = wrong key, IndexError = list too short, TypeError: list indices... = a key used on a list.

EC2: the Reservations → Instances Shape

  • describe_instances returns reservations that contain instances. A reservation is only a launch request, so flatten first.
  • A reservation is just one launch request, so its grouping is meaningless for your purposes — always flatten first.
  • Reading ["Reservations"][0] silently ignores the rest. Use a nested comprehension.
  • Real responses carry datetime objects; here they're ISO strings so the data is easy to read.
  • Use .get(..., []) at both levels so empty or partial responses give an empty list, not a crash.
  • It returns Reservations, each holding Instances.

Pagination: Why APIs Answer in Pages

  • APIs cap each answer so no single reply is huge; a token is a bookmark for the next page.
  • Loop: call, use the page, stop if nothing more remains, otherwise carry the token to the next call.
  • Wrap the loop in a generator (or use boto3's paginator) so callers write a plain for.

Errors, ClientError, Throttling and Backoff

  • Throttling means "too fast": wait and retry. Timeouts and 5xx are transient too; AccessDenied and bad input are permanent.
  • An error carries a dict: e.response["Error"]["Code"] decides what to do.
  • Exponential backoff doubles the wait up to a cap; jitter randomises it so clients do not retry in lock-step.

The Skill Behind Every Cloud Script: Handling the Response

  • Almost every DevOps script you'll write for AWS, Kubernetes or Docker has the same shape: call an API → get a big nested JSON document back → walk it → decide something (delete it, alert on it, total it, report it).
  • Now the first response-handling trap, and it's a real one: boto3 omits the Tags key entirely when a resource has no tags — it is not an empty list.
  • The value — and nearly every bug — lives in handling the response: keys that are silently missing, results that are paginated, units like 250m and 2Gi, errors that should or shouldn't be retried.

IAM Policy Review: Reading Wildcards Programmatically

  • Least privilege means a role gets exactly the actions it needs on exactly the resources it needs.
  • Parsing them has a well-known snag: IAM lets Statement, Action and Resource each be a single value or a list, so you normalise before you loop.

Kubernetes: kubectl get pods -o json → Triage

  • The pod's status.phase is coarse (Pending/Running/Succeeded/Failed); the detail is in status.containerStatuses[*].state.waiting.reason, lastState.terminated, and the conditions list.
  • The trick is knowing where each symptom lives.

Resource Quantities, Requests vs Limits, and QoS

Docker: inspect JSON, Image References and Container Hygiene

  • docker inspect returns the full configuration and state of a container as JSON, and the SDK's container.attrs is that same document.
  • It's easy to get wrong because a registry host can contain a colon (a port), so localhost:5000/cache/redis has a colon that is not a tag separator.

Watch out

  • Which blocks can you run? The real boto3, kubernetes and docker libraries need real credentials and a network, which this in-browser Python does not have.
  • Never put access keys in a script or a repo Keys committed to a repository are the classic breach. On EC2, ECS and EKS the SDK finds credentials by itself (instance profile, task role, IRSA).
  • Reference code — not runnable in this browser. boto3, the kubernetes client and the docker SDK needs real credentials and a real network, which this WebAssembly sandbox doesn't have, so there is no ▶ Run button.
  • Never put access keys in a script or a repo. On EC2, ECS and EKS the SDK finds credentials by itself (instance profile, task role, IRSA). Locally it reads ~/.aws or environment variables.
  • Rules that reference other groups aren't CIDRs. A rule can allow traffic from another security group (UserIdGroupPairs) instead of an IP range.
  • Three things that fool every first attempt. 1. A pod in ImagePullBackOff reports phase: Pending, not Failed — the containers never started. 2. A finished Job's pod has Ready=False on purpose (reason…
  • 1G is not 1Gi. 1G is 1,000,000,000 bytes (953.67 MiB); 1Gi is 1,073,741,824 (1024 MiB). The gap is about 7%, so a sloppy parser makes capacity numbers drift. Note also that m means milli for CPU.
  • Retries need idempotency. Retrying a read is always safe. Retrying a create can make two of the thing if the first call actually succeeded but the response was lost.
