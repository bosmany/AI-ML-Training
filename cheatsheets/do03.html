DevOps 3: Automation Scripts & Resilience

Compiled from the chapter text on 2026-09-21. A study aid: the lesson has the explanations and the caveats.

In short

  • Test on a throwaway tree, and guard every delete — resolve paths and check they sit inside the allowed root before removing anything.
  • Separate the plan from the action. A pure planner with an injected now gives you dry-runs, deterministic tests and replayable history.
  • Retention = age rule OR newest-K rule. The count rule stops a broken backup job from causing a total wipe.
  • Retry transient errors only, with bounded attempts, exponential backoff, a cap and jitter — and only for operations that are safe to repeat.
  • Idempotent, atomic, locked: declare end state, write temp-then-os.replace, and serialize runs with an exclusive lock that is always released.
  • Exit codes are the API to your scheduler; structured logs are the API to your log platform. Return codes from main(), log JSON, never log secrets.
  • Cron has sharp edges: Sunday is 0 (or 7), day-of-month and day-of-week combine with OR, and schedules run in server-local time.
  • Never build shell strings from input. Use argument lists, timeouts and check=True; handle SIGTERM; reap child processes.

Key ideas by section

What an Automation Script Is, and What "Safe in Production" Means

  • An automation script runs unattended, so it must supervise itself; safe in production means harmless on a bad day and honest about what happened.
  • Split every script into a pure plan (returns data) and an apply step (changes things), with a dry run in between.
  • Make the safe behaviour the default, and add cheap guard rails such as a circuit breaker.

The Filesystem as a Tree, and Paths as Objects

  • A filesystem is a tree; a path is a file's address, absolute (from the root) or relative (from here).
  • Path objects join with / and expose .name, .stem, .suffix, .parent, .parts; they never touch the disk until you ask.
  • iterdir is one level, glob is a pattern on one level, rglob is every level. Sort for stable order.

Safe Sandboxes and Safe Deletes: tempfile and shutil

  • Compare locations, not spellings: resolve() first, then is_relative_to().
  • tempfile.TemporaryDirectory() is a throwaway sandbox that removes itself; use it for practice and tests.

A Disk-Usage Report You Can Test

  • A usage report is group and sum: one bucket per top-level folder, filled with totals.get(key, 0) + size.
  • Return numbers from one function and format them in another, so the numbers can be tested.

Hashing Files to Find Duplicates

  • A hash is a fixed-length fingerprint of data: same input gives the same digest, any change gives a different one.
  • Hash bytes, and feed big files in chunks with update() so memory stays flat.

Filesystem Automation With pathlib, shutil and tempfile

  • Two habits matter more than the API: build test data in a throwaway directory (tempfile.mkdtemp() or TemporaryDirectory()) so your automation never has to be tried out on real data, and make every step safe to repeat…
  • pathlib.Path is the modern way to touch the filesystem from a script: paths are objects, / joins them, and .parent, .name, .suffix, .read_text(), .rglob() replace a pile of os.path.join calls and string slicing.

A Disk-Usage Report (the du -sh You Can Test)

  • The recipe is always the same: walk the tree with rglob('*'), keep only files (is_file()), attribute each file's st_size to a bucket (here, the top-level directory), then sort.
  • Writing the same thing in Python is worth it the moment you need to run it on a schedule, alert on a threshold, or post the result to a chat channel.

Finding Duplicate Files by Content

  • Hash in fixed-size chunks so memory stays flat no matter how large the file is — path.read_bytes() on a 50 GB file is an out-of-memory kill waiting to happen.
  • Duplicate detection is a good example of writing automation that scales.

Retention and Rotation Policies With an Injected Clock

  • Three design decisions keep it safe. One: compute a plan (what to keep, what to delete) as a pure function, and only then act on it — that makes a dry-run trivial. Two: never call datetime.now() inside the logic; pass now in.
  • The function becomes deterministic, unit-testable at any date, and you can replay "what would have been deleted last Tuesday." Three: combine an age rule with a count rule — keep anything newer than N days or among the newest K. The count rule is the seatbelt.

Retries With Exponential Backoff and Jitter

  • And selectivity: retry only errors that can plausibly succeed next time (ConnectionError, TimeoutError, HTTP 429/502/503/504) — never a ValueError or a 400/404, because a malformed request stays malformed.
  • The standard recipe has four parts. Bounded attempts (a budget, not infinity). Exponential backoff: wait 1s, 2s, 4s, 8s… so a struggling service gets breathing room, capped at a max_delay. Jitter: randomize each wait so a…

Idempotency, Atomic Writes and Locks

  • A script is idempotent if running it twice leaves the system in the same state as running it once.
  • The simplest portable lock is a file created with the exclusive-create flag: open(path, 'x') succeeds for exactly one caller and raises FileExistsError for everyone else.

Exit Codes, argparse Subcommands and Structured Logging

  • Plain print lines are fine for a human; structured (JSON) logs let Loki, CloudWatch, Datadog or jq filter on fields — level == "ERROR", file == "db-2025-01-01.sql.gz" — instead of regex-ing prose.
  • When your script runs under cron, a CI job, a Kubernetes Job or a systemd unit, nobody reads its output — the scheduler looks at the exit code.

Cron Expressions: Knowing When Your Script Runs

  • Most of the scripts in this chapter run from cron or something that copies its syntax (Kubernetes CronJob, GitHub Actions schedule, CloudWatch rules).
  • Five fields — minute hour day-of-month month day-of-week — each accepting *, a number, a list (1,15), a range (1-5), and a step (*/5, 10-50/10).

Running Other Programs Safely: subprocess, Signals and Parallel Host Checks

  • Sooner or later a script has to call git, kubectl, rsync or pg_dump. subprocess needs a real operating system, so the real calls below are reference only in this browser sandbox — but the injection problem they defend against you can demonstrate right here with shlex.
  • The rule is simple: pass an argument list, never a shell string built from input.

Watch out

  • Resolve first, then compare. Checking str(target).startswith(str(root)) on the raw path is a classic bug: /data/backups-old starts with /data/backups, and /data/backups/../secrets passes the string…
  • Why "newest K" matters. Look at the second call: the backup job broke in January, so by March every backup is older than 7 days.
  • Only retry what is safe to repeat. If the request might have succeeded before the connection dropped, retrying a non-idempotent call (POST /charge, "send email", "increment counter") can double-apply it.
  • Stale locks. A file lock survives a kill -9 or a power loss, so the next run is locked out forever.
  • Read the fifth and sixth lines again. 0 0 13 * 5 reads like "midnight on Friday the 13th," but it fires on every Friday and on every 13th — the OR rule.
