Ch 15: ML Foundations & Workflow

Compiled from the chapter text on 2026-09-21. A study aid: the lesson has the explanations and the caveats.

In short

  • X (2D feature matrix) and y (label vector) — the shape of every supervised learning problem.
  • train_test_split(X, y, test_size=..., random_state=...) holds out unseen data so evaluation is honest.
  • Underfitting = too simple, bad everywhere. Overfitting = too complex, great on train, worse on test.
  • Bias-variance tradeoff: simplicity fights complexity — you can't minimize both errors at once.
  • accuracy / precision / recall / F1 — computed by hand from TP/FP/FN/TN, or via sklearn.metrics. Accuracy alone is misleading on imbalanced data.
  • The workflow: split → fit → predict → evaluate. Every chapter from here reuses this exact loop.

Key ideas by section

What "Training" a Model Actually Means

  • A supervised ML problem has two parts: a matrix of features X (the inputs — one row per example, one column per measurement) and a vector of labels y (the known correct answers).
  • "Training" means running an algorithm that searches for parameters making the model's predictions match y as closely as possible ON THE DATA IT SEES.
  • Chapter 10 already built this from scratch with gradient descent — Module 4 is about the sklearn library that packages the same idea behind .fit() and .predict().

Train/Test Split: The Most Important Line in ML

  • If you train a model AND evaluate it on the exact same data, you learn nothing about whether it generalizes — a model that just memorizes the answer key will score perfectly and still fail on anything new.…

Overfitting vs Underfitting

  • Underfitting: the model is too simple to capture the real pattern — it does poorly on both training AND test data. Overfitting: the model is complex enough to memorize noise and quirks specific to the training data — it does GREAT on training data but noticeably worse on test data.
  • The gap between train accuracy and test accuracy is the tell-tale sign of overfitting.

The Bias-Variance Tradeoff

  • Every model sits somewhere on this spectrum, and total error is roughly bias² + variance + irreducible noise.
  • You cannot drive both to zero at once — reducing one usually raises the other, which is exactly what depth 1 vs depth None showed above.

Classification Metrics, By Hand

  • For a binary classifier, every prediction falls into one of four buckets against the truth: True Positive (predicted 1, actually 1), False Positive (predicted 1, actually 0), False Negative (predicted 0, actually 1), True Negative (predicted 0, actually 0).

The Same Metrics via sklearn.metrics

  • You'll never hand-roll the TP/FP/FN/TN loop in real code — sklearn.metrics provides accuracy_score, precision_score, recall_score, f1_score, and confusion_matrix (the 2×2 grid of those four counts), plus classification_report which prints all of them at once, per class.

Putting It Together: The ML Workflow

  • Every classical ML chapter from here follows this exact shape: split the data, fit a model on the training set, predict on the test set, evaluate with metrics.
  • This is the whole loop — everything else in Module 4 (which model, which features, which settings) is a variation on these four verbs.

Watch out

  • Never touch the test set until final evaluation — not to pick features, not to tune settings, not "just to check." Every peek that influences a decision leaks information from the test set into your…
  • Accuracy lies on imbalanced data. If 95% of candidates are NOT qualified, a model that predicts "not qualified" for everyone scores 95% accuracy while catching zero actual positives (recall = 0).
