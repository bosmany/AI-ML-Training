Ch 4: Data Structures

Compiled from the chapter text on 2026-09-21. A study aid: the lesson has the explanations and the caveats.

In short

  • Collections hold many values under one name, so code does not depend on how many values there are. Choose by the question you will ask: position (list), fixed record (tuple), label lookup (dict), uniqueness and membership (set).
  • Lists are ordered and mutable. Indexes count from 0 (negative from the end); slices [start:stop:step] build new lists and exclude the stop. An index past the end raises IndexError.
  • In-place methods (append, sort, remove, ...) return None, so never write x = x.sort(). sorted(x) returns a new list.
  • Assignment copies name tags, not objects: b = a is an alias. Use .copy(), list(x) or x[:] for a copy, and copy.deepcopy for nested data.
  • Tuples are immutable. Unpacking (x, y = pair) splits them by position, and the counts must match or you get a ValueError.
  • Dicts map hashable keys to values. Use d.get(key, default) when the key may be missing, d.items() to loop over pairs, and expect KeyError from d[key] on a missing key.
  • Sets store unique values with fast in tests. &, |, -, ^ compare groups; print with sorted(...). An empty set is set(), not {}.
  • Lists of dicts are the shape of real datasets and nested dicts are the shape of JSON. Read d["a"][0]["b"] one step at a time, and rank records with sorted(data, key=lambda r: r["field"]).
  • collections and unpacking: Counter counts, defaultdict groups, namedtuple names the parts of a record; first, *rest = items splits a list and {**a, **b} merges dicts (later wins).
  • Comprehensions build lists, dicts and sets from another collection: [x for ...], {k: v for ...}, {x for ...}.

Key ideas by section

Why We Need Collections: One Name for Many Values

  • A collection holds many values under one name, so code does not depend on how many values there are.
  • Python has four built-in collections: list, tuple, dict and set.
  • Ordered means items have positions; mutable means the collection can be changed after it is created.

Reaching Inside a List: Indexing and Slicing

  • An index is a position counted from 0; negative indexes count from the end (-1 is the last).
  • A valid index for a list of length n runs from -n to n - 1; anything else raises IndexError.
  • A slice [start:stop:step] builds a new list and excludes the stop position.

Changing a List: In-Place Methods versus New Lists

  • Methods that change a list (append, sort, remove, ...) return None, so never assign their result.
  • sorted(x) returns a new sorted list; x.sort() reorders x itself.
  • append adds one item, extend adds each item of another list.

Two Names, One List: Aliasing versus Copying

  • A variable is a name tag on an object, and b = a puts a second tag on the same object.
  • With mutable objects this is aliasing: changing through one name shows through the other. is tests for it.
  • Make an independent list with .copy(), list(x) or x[:].

Tuples: Fixed Records and Unpacking

  • A tuple is an ordered, immutable collection written with (); indexing and slicing work like a list.
  • Assigning to a tuple item raises TypeError.
  • A one-item tuple needs a trailing comma: (5,).

Dictionaries: Looking Things Up by Name

  • A dict stores key: value pairs and looks values up by key, written d[key].
  • d[key] = v adds a new pair or replaces the value of an existing key.
  • del d[key] and d.pop(key) remove a pair; pop returns the value.

Safe Lookups, Looping Over Dicts, and Which Keys Are Allowed

  • d.get(key, default) reads without ever raising KeyError; the default is None if you omit it.
  • A for loop over a dict yields keys; use .values() for values and .items() for (key, value) pairs.
  • Do not add or remove keys while looping over the same dict.

Sets: Unique Items, Fast Membership, and Comparing Groups

  • A set stores each value once and has no order or positions; make an empty one with set(), not {}.
  • add inserts, discard removes safely, remove raises KeyError if the value is missing.
  • in on a set is fast because it uses hashing; a list has to check items one by one.

Choosing the Right Collection

  • Choose by the question you will ask: position (list), fixed record (tuple), lookup by label (dict), membership and uniqueness (set).
  • You can convert between them: dict(pairs), list(d), set(items), tuple(items).
  • Mixing shapes is normal: lists of dicts and dicts of lists appear everywhere in real data.

Lists of Dicts: The Shape of Real Data, and Sorting It

  • A list of dicts is a dataset: each dict is a record and each key is a column.
  • records[i]["field"] first picks a record by position, then a field by key.
  • sorted cannot compare dicts; pass key= with a function that returns the value to compare.

Nested Data and the JSON Shape

  • Collections nest: dicts hold lists, lists hold dicts, dicts hold dicts. JSON is that same shape written as text.
  • Read a chain like d["a"][0]["b"] left to right, one step at a time; use a key for a dict and an index for a list.
  • TypeError: list indices must be integers means you used a key on a list; a KeyError usually means the wrong level.

The collections Module: Counter, defaultdict, namedtuple

  • Counter(items) counts occurrences; .most_common(n) lists the top n as (item, count) tuples.
  • defaultdict(list) creates an empty list for any missing key, which removes the if key not in d guard when grouping.
  • namedtuple gives a tuple named fields (record.score) and stays immutable.

Star and Double-Star: Splitting and Merging

  • first, *rest = items gives the leftovers to the starred name, always as a list (possibly empty); only one star is allowed.
  • [*a, *b] builds a list from two lists, and f(*items) passes items as separate arguments.

Comprehensions over Lists, Dicts and Sets

  • A comprehension is [value for item in source if condition]; the brackets decide the result: [...] list, {k: v ...} dict, {x ...} set.
  • Loop over d.items() to get key and value together; a bare for k, v in d fails with a ValueError.

Watch out

  • Rule of thumb: if a list method changes the list, it returns None. Do not write x = x.sort(), x = x.append(5) or x = x.reverse().
  • The one-item trap: (5) is only the number 5 inside brackets. A tuple of one item needs a trailing comma: (5,). In fact it is the commas that make a tuple, not the brackets: x = 1, 2 is also a tuple.
  • Do not add or remove keys while looping over the same dict. Python cannot keep track of where it is. Loop over a copy of the keys instead: for k in list(d):.
  • Two traps. An empty pair of curly brackets {} makes an empty dict, not a set. Write set() for an empty set.
  • Side effect: merely reading a missing key from a defaultdict adds it. If you only want to peek, use key in d or d.get(key).
