DSA 3: Dynamic Programming & Greedy Algorithms

Compiled from the chapter text on 2026-09-21. A study aid: the lesson has the explanations and the caveats.

In short

  • DP applies when a problem has optimal substructure (best answer built from best sub-answers) AND overlapping subproblems (those sub-answers repeat) — memoized Fibonacci from DSA 2 already was DP, just top-down.
  • Bottom-up (tabulation) builds the answer iteratively into an explicit dp array/table — no recursion, no stack-depth risk, and the table fill is directly observable.
  • 1D DP (climbing stairs, coin change) needs one index per sub-problem; 2D DP (LCS) needs two, giving an O(m·n) table.
  • Greedy is faster and simpler than DP but only correct for problems with a provable "safe choice" property (activity selection) — it can and does fail on problems that look similar but lack that property (0/1 knapsack).
  • The real interview skill isn't memorizing solutions — it's recognizing WHICH shape a new problem has: is there a safe greedy choice, or do I need to consider combinations systematically with DP?

Key ideas by section

What DP Actually Is: Optimal Substructure + Overlapping Subproblems

  • This chapter's new piece is bottom-up DP: build the answer iteratively from the smallest sub-problem up, storing every intermediate result in an explicit dp array — no recursion, no call stack risk, and it makes the "table filling in" visible.

2D DP: When One Index Isn't Enough

  • Some problems need TWO indices to describe a sub-problem — Longest Common Subsequence (LCS) is the classic example: "what's the longest sequence that appears in both s1[0:i] AND s2[0:j]?" needs both i and j, so the DP table is 2D.
  • The recurrence: if the current characters match, extend the diagonal's answer by 1; if they don't, take the best of "drop this character from s1" or "drop this character from s2."

Greedy Algorithms: Fast, Simple, and Not Always Correct

  • A greedy algorithm makes the locally-best choice at each step and never reconsiders it — no table, no backtracking, just one pass.
  • It's much simpler and faster than DP when it works — but it doesn't always find the truly optimal answer, and knowing WHICH problems it's safe for is the actual skill.
