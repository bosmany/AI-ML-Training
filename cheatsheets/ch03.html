Ch 3: Functions & Modules

Compiled from the chapter text on 2026-09-21. A study aid: the lesson has the explanations and the caveats.

In short

  • Why functions: copy-pasted logic is hard to fix and hides intent. A function is a named block you write once (DRY) and call many times.
  • Define versus call: def name(params): writes the function and runs nothing; name(args) runs it. Without parentheses you only name it.
  • Parameters and arguments: parameters are in the definition, arguments in the call. Match by position or by keyword (name=value), positional first.
  • The call stack: every call gets a private frame, and only the top frame runs. A traceback is the stack, read bottom-up.
  • return versus print: return hands a value back; print only displays. No return means None. return a, b gives a tuple you can unpack.
  • Defaults and star-arguments: x=4 makes a parameter optional. Never use a list as a default; use None. *args collects a tuple, **kwargs a dictionary.
  • Scope (LEGB): names are local to the function; lookup goes Local, Enclosing, Global, Built-in. Prefer return over global.
  • Recursion: a function that calls itself needs a base case, and each call gets its own frame.
  • lambda: a one-expression, nameless function, mostly used as key= for sorted, max and min.
  • Docstrings and type hints: document what a function does and what it takes and returns. Hints are not enforced.
  • Closures and nonlocal: a returned inner function remembers the outer variables; nonlocal lets it change them.
  • functools: partial pre-fills arguments, reduce folds items into one value, @lru_cache remembers answers.
  • The standard library: import math, from math import sqrt, import x as y; random.seed for repeatable randomness, plus datetime and collections.
  • Modules: a module is a .py file found through sys.modules and sys.path. Use if __name__ == "__main__": so a file is both importable and runnable.

Key ideas by section

Why Functions? The Pain of Copy-Paste

  • Copy-pasted logic must be fixed in every copy, hides the intent of the program, and has no name.
  • The rule is DRY: keep each piece of logic in exactly one place.
  • A function is a named block of code. You write it once and call it as often as you like, like a recipe card you reuse with different ingredients.

A Function Is a Machine: Defining Versus Calling

  • A function is a machine: inputs go in, the body runs, an output comes back.
  • def name(parameters): followed by an indented body defines a function and runs nothing.
  • name(...) calls it. Without the parentheses you only refer to the function.

Parameters and Arguments: Positional and Keyword

  • Parameters are the names in the def line; arguments are the values in the call.
  • Positional arguments match by order; keyword arguments (name=value) match by name and can come in any order, but only after all positional ones.
  • A call that does not fit the definition fails with a TypeError that names the function and the parameter, or with a SyntaxError for positional-after-keyword.

What Happens During a Call: Nested Calls and the Call Stack

  • Each call creates a frame holding that call's own parameters and variables; frames are stacked, and only the top one runs.
  • When a function returns, its frame is thrown away and Python resumes exactly where the call was made.
  • A traceback is the call stack printed out: read it from the bottom (the error) upwards (who called whom).

return vs print: Handing a Value Back

  • return value ends the function and hands the value back to the caller; the call then acts as that value.
  • print only displays. A function without return gives back None, which causes NoneType errors later.
  • Several return lines are fine, because only one runs. return a, b gives back a tuple you can unpack.

Default Values, a Famous Trap, and *args / **kwargs

  • name=value in a definition makes a parameter optional; defaulted parameters go after required ones.
  • A default is created once, when def runs, so a list default is shared between calls. Use None and create the list in the body.
  • *args collects extra positional arguments into a tuple; **kwargs collects extra keyword arguments into a dictionary.

Scope: Which Names Can a Function See?

  • Variables assigned inside a function are local: they exist only during the call.
  • Python looks names up in the order Local, Enclosing, Global, Built-in.

Recursion: A Function That Calls Itself

  • Recursion means a function calls itself on a smaller version of the problem.
  • Every recursive function needs a base case that stops the calls, and a recursive case that moves toward it.

lambda: A Tiny Function Without a Name

  • lambda params: expression builds a small anonymous function whose expression value is returned automatically.
  • Its main use is as the key for sorted, max and min, which call it on each item.

Docstrings and Type Hints: Explaining Your Functions

  • A docstring is a triple-quoted string as the first line of a function body; read it with help(f) or f.__doc__.
  • Type hints (x: int, -> float, -> None) document the inputs and output but are never enforced by Python.

Closures and nonlocal: Functions That Remember

  • A function can return a function. The inner function remembers variables from the outer one: a closure.
  • Each call of the outer function makes a separate set of remembered variables.

functools: Ready-Made Tools for Functions

  • partial(f, ...) builds a simpler function with some arguments already filled in.
  • reduce(f, items) folds a sequence into one value by combining pairs.

Using Python's Standard Library: math, random, datetime, collections

  • import module gives access via module.name; from module import name gives the bare name; as renames.
  • The standard library is a big set of modules: math, random, datetime, collections and many more.

How import Finds Modules, Writing Your Own, and __main__

  • A module is a .py file; import finds it via sys.modules and sys.path, runs it once and gives you a module object.
  • Your own folder is searched first: never name your files after standard modules.

Watch out

  • Beginner trap: if a path through the function reaches the end without hitting return, the result is None.
  • Use with care: caching only makes sense for functions whose answer depends solely on their arguments. If a function reads a global or the clock, a cached answer may be stale.
