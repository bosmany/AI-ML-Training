Ch 12: Pandas Fundamentals

Compiled from the chapter text on 2026-09-30. A study aid: the lesson has the explanations and the caveats.

In short

  • DataFrame = a table (rows + named columns). Series = a single column.
  • pd.read_csv() loads and type-converts a CSV in one line — always verify row count, columns, and nulls after loading.
  • .loc selects by label; .iloc selects by position.
  • df[condition] and .query() both filter rows. Never chain a filter and an assignment in one bracketed expression — use .loc[rows, col] = value.
  • .sort_values() ranks by any column. .groupby().agg([...]) computes multiple summaries per category at once.
  • .merge() (inner/left/right/outer) joins on a key — check for duplicate keys first, or row counts can silently multiply.
  • .pivot_table() reshapes long data into a wide summary grid.
  • Vectorized operations beat .apply(), especially row-wise (axis=1) apply — reach for apply only when vectorization genuinely isn't possible.
  • pd.to_datetime() turns date strings into a real dtype — needed for correct sorting/filtering and for .resample().

Key ideas by section

DataFrame: The Spreadsheet Inside Python

  • A DataFrame is a table: rows and named columns, like a spreadsheet.
  • A Series is a single column (or row) of it.
  • A DataFrame is that same idea, but built for fast, convenient bulk operations.

Reading a Real CSV File

  • Pandas does the whole thing — including type conversion — in one line: pd.read_csv().
  • The running example for the rest of this chapter is a real, 1,500-row e-commerce orders dataset (plus a 50-row customers lookup table) — generated once with a fixed seed so it's exactly reproducible, then written to a real CSV and read back exactly like any file you'd download.
  • Chapter 5 parsed CSVs manually with the csv module.

Indexing: .loc vs .iloc

  • .iloc selects by integer POSITION (like a list index). .loc selects by LABEL (the actual index value, or column name) — for a default DataFrame these often look the same, but they mean different things and diverge the moment your index isn't a simple 0,1,2....

Filtering Rows

  • One filtering mistake is common enough to have its own name: chained assignment — trying to filter AND assign in one bracketed expression.
  • .query() is a readable alternative to boolean masking — the condition is a plain string, so no repeating df[...] for every column, and no bare &/| operator-precedence surprises.
  • Same boolean-masking idea from Chapter 11, applied to a DataFrame: df[condition] keeps only the matching rows.

Sorting

  • .sort_values('column') sorts a DataFrame by any column, ascending by default.

GroupBy: Aggregating by Category

  • .groupby('column') splits a DataFrame into groups sharing a value, so you can aggregate each group separately — "average score PER department," not just overall.
  • One aggregation per group is often not enough — .agg() computes SEVERAL at once, on the real orders data.

Merging: Inner, Left, Right, and Outer

  • A merge (also called a join) combines two DataFrames using a shared key column — exactly like joining tables in SQL.
  • The four kinds differ only in which UNMATCHED rows they keep: inner keeps only rows with a match on both sides; left keeps every left row (filling unmatched right columns with NaN); right is the mirror image; outer keeps everything from both sides.
  • The most common real merge bug isn't picking the wrong join type — it's an unexpected duplicate key, which silently multiplies rows instead of erroring.

Pivot and Pivot Table

  • .pivot_table() reshapes long data into a wide summary grid: one column's values become new COLUMN HEADERS, another becomes an aggregated VALUE — the pandas equivalent of a spreadsheet pivot table.

apply() vs Vectorized Operations

  • .apply() runs a Python function once per row (or column) — flexible, but it's a Python-level loop underneath, with all of Chapter 11's loop overhead.
  • If the same computation can be written as a vectorized expression, that's almost always faster, and often more readable too.

Datetime: Parsing, Extraction, Filtering, and Resampling

  • A date read from CSV is just a STRING until you tell pandas otherwise. pd.to_datetime() converts it to a real datetime dtype — unlocking .dt accessors, correct chronological comparisons, and resampling (aggregating into fixed time buckets like "per month").

Readable Method Chaining

  • Every operation above returns a NEW DataFrame or Series — which means they can be chained directly, one .method() per line, instead of reassigning a variable at every step.
  • Parenthesize the whole expression and it reads almost like a sentence.

Watch out

  • Real output: the chained-assignment line prints a ChainedAssignmentError warning explaining that "this never works to update the original DataFrame," and then execution continues normally — no exception, no crash.
  • Real output: 3 orders become 5 merged rows — orders 2 and 3 (both customer_id=20) each matched BOTH duplicate lookup rows, producing every combination.
  • Real output: results match: True, apply best-of-5 ~0.0125s, vectorized best-of-5 ~0.000094s — about 130x faster (exact numbers will differ on your machine, same methodology as Chapter 11's timing).…
  • Real output: as strings, October ('2023-10-2') sorts BEFORE February ('2023-2-1') — alphabetical comparison, not chronological, because '1' < '2' as characters.
