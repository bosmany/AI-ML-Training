36.1 — What Is FastAPI, and Why Can't It Run In This Console

FastAPI is an ASGI (Asynchronous Server Gateway Interface) web framework: you declare routes with Python decorators, and FastAPI uses your function's type hints to parse, validate, and document incoming requests automatically — the same job Flask/Django leave to you and a separate schema/serializer library. Running a real FastAPI app means starting uvicorn, an ASGI server that binds an actual OS network socket and listens for HTTP connections — something a WebAssembly sandbox like Pyodide fundamentally cannot do, for the same reason it can't load PyTorch: no native OS process, no real sockets.

🎬

Colab / real Python — the smallest possible FastAPI app
from fastapi import FastAPI app = FastAPI(title="Candidate Scoring API") @app.get("/health") def health(): return {"status": "ok"}
⭐
You never call health() yourself. FastAPI calls it whenever a real request hits GET /health. In this module, "a real request" almost always means TestClient driving the app in-process (36.7) — deterministic, no port, no network, works identically in Colab and in production.
36.2 — Your First Endpoint: Path Parameters

A path parameter is a variable segment of the URL, written as {name} in the route and matched to a function argument of the same name. Type-hint it, and FastAPI converts and validates it for you — candidate_id: int means "parse this URL segment as an integer, or reject the request before my function even runs."

Colab / real Python — a typed path parameter
from fastapi import FastAPI app = FastAPI() CANDIDATES = { 1: {"name": "Alice", "score": 0.92}, 2: {"name": "Bob", "score": 0.75}, 3: {"name": "Carol", "score": 0.81}, 4: {"name": "Dave", "score": 0.60}, 5: {"name": "Eve", "score": 0.55}, } @app.get("/candidates/{candidate_id}") def get_candidate(candidate_id: int): return CANDIDATES[candidate_id]
💡
Requesting /candidates/abc never reaches your function. FastAPI can't parse "abc" as an int, so it automatically returns a 422 Unprocessable Entity with a validation error body — see 36.6.
36.3 — Query Parameters

Any function parameter that ISN'T in the route's {...} path becomes a query parameter instead — read from the URL's ?key=value section. Give it a default value and it becomes optional.

Colab / real Python — an optional query parameter with a default
from typing import Optional @app.get("/candidates") def list_candidates(min_score: float = 0.0, name: Optional[str] = None): results = [c for c in CANDIDATES.values() if c['score'] >= min_score] if name: results = [c for c in results if c['name'].lower() == name.lower()] return results # GET /candidates -> all 5 candidates # GET /candidates?min_score=0.8 -> Alice, Carol # GET /candidates?min_score=0.8&name=Alice -> just Alice
36.4 — Pydantic Request Bodies

A Pydantic BaseModel declares the shape of incoming JSON. FastAPI parses the request body into an instance of it automatically — reject-if-invalid, no manual json.loads or hand-written checks. Field(...) adds constraints beyond the plain type.

Colab / real Python — a validated request model
from pydantic import BaseModel, Field class CandidateIn(BaseModel): name: str score: float = Field(gt=0, le=1) # must be > 0 and <= 1
⭐
This is the same "declare the shape, get validation for free" idea as Chapter 4's dictionaries — except now the shape is enforced automatically on every request, with a precise error if it's violated, instead of you writing if checks by hand.
36.5 — Response Models & Status Codes

response_model= declares the shape of what a route RETURNS — FastAPI filters your return value down to exactly those fields (dropping anything extra) and documents that shape in the auto-generated API docs. status_code= sets the HTTP status for a successful response — 201 Created is the convention for a successful POST that creates something new.

Colab / real Python — POST with a response model and a 201
from pydantic import BaseModel class CandidateOut(BaseModel): id: int name: str score: float @app.post("/candidates", response_model=CandidateOut, status_code=201) def create_candidate(candidate: CandidateIn): new_id = max(CANDIDATES) + 1 CANDIDATES[new_id] = candidate.model_dump() return {"id": new_id, **candidate.model_dump()}
36.6 — What A Validation Error Actually Looks Like

When a request fails validation, FastAPI returns 422 with a JSON body listing every failing field — loc (where the bad value was), msg (why it failed), and type (a machine-readable error code). Posting {"name": "Frank", "score": 5} against 36.4's model (which requires score <= 1) produces something shaped like this:

Real 422 response body shape (exact wording varies by Pydantic version)
{ "detail": [ { "loc": ["body", "score"], "msg": "Input should be less than or equal to 1", "type": "less_than_equal" } ] }
💡
You never write this response by hand. Pydantic raises a ValidationError, FastAPI catches it, and turns it into this exact 422 shape automatically — for every route, for free.
36.7 — Testing With TestClient

fastapi.testclient.TestClient wraps your app and drives it in-process — it calls straight into your ASGI app's code, with no real socket, no port, no network stack. This is exactly how every exercise and notebook cell in this module actually runs your FastAPI code: write the app, wrap it in a TestClient, then call .get()/.post() on it just like a real HTTP client.

Colab / real Python — testing the Candidate Scoring API
from fastapi.testclient import TestClient client = TestClient(app) response = client.get("/candidates/1") assert response.status_code == 200 assert response.json()["name"] == "Alice" response = client.post("/candidates", json={"name": "Frank", "score": 0.70}) assert response.status_code == 201 print(response.json())
🚫
TestClient is not a stand-in for real deployment. It proves your route logic and validation are correct, but skipping past it straight to "it works" without ever running a real uvicorn server is a mistake — Chapter 41's capstone runs one for real to close that gap.
Chapter 36 Summary
  • FastAPI can't run live in this browser because a real server needs a real network socket — same limit as PyTorch, different reason.
  • Path parameters ({id}) and query parameters (plain function args with defaults) are both type-validated automatically.
  • Pydantic BaseModel declares and validates request bodies; Field(...) adds constraints.
  • response_model= and status_code= declare and document what a successful response looks like.
  • TestClient drives the app in-process with no real socket — this is how the whole module actually executes and grades FastAPI code.
