1.1 — What Is a Program? What Is Python?

Suppose you train a small model to tell cats from dogs, and every evening you want to know how well it did. By hand, that means opening a list of 500 guesses, marking each one right or wrong, counting the right ones, dividing, and writing the result down. It takes an hour, and tomorrow you must do it again. This is the kind of job computers are for, but a computer cannot guess what you want. You have to write the job down in a form it understands.

That written-down job is a program: a list of instructions that a computer follows one after another, exactly as written. The best everyday comparison is a cooking recipe. A recipe is a list of steps in a fixed order, and a cook who follows it exactly gets the same dish each time. A program is the recipe, and the computer is the very literal cook. If a step is missing, the cook does not improvise. If two steps are in the wrong order, you get a strange dish.

The words you write make up code. When the computer carries the instructions out, we say you run the code (or execute it). Code has to be written in a programming language, a strict, small vocabulary with fixed grammar rules. Ours is Python, created by Guido van Rossum and first released in 1991. Something has to read your Python and act on it: a program called the interpreter. It reads your file from the top, one line at a time, and does what each line says.

From your idea to a result
  YOU write code   PYTHON INTERPRETER   RESULT
  ┌──────────────┐   ┌────────────────┐   ┌─────────┐
  │ print('hi')  │─> │ reads line 1,  │─> │ hi      │
  │ print('bye') │   │ then line 2    │   │ bye     │
  └──────────────┘   └────────────────┘   └─────────┘
   the recipe        the literal cook     the dish

Here is the smallest useful program: three steps, each one a print instruction. print tells Python to show something on the screen. Do not worry about the exact spelling yet; the next section shows you how to run code. For now, read the code and predict the order of the output before you look at it.

Your first program: three steps, in order
print('Step 1: load the photos') print('Step 2: train the model') print('Step 3: report the score')
Output
Step 1: load the photos Step 2: train the model Step 3: report the score

What Python does, line by line. (1) It reads the first line, sees print, and shows the text between the quotes. (2) It moves down one line and does the same. (3) It moves down again. (4) It reaches the end of the file and stops. Nothing runs in parallel and nothing is skipped. The order on the screen is the order in the file.

Now change one thing. Swap two lines and see that the computer does not care what makes sense. It only cares what is written.

Same steps, wrong order
print('Step 3: report the score') print('Step 1: load the photos') print('Step 2: train the model')
Output
Step 3: report the score Step 1: load the photos Step 2: train the model

The output is now in a silly order, and Python raised no complaint, because every line was valid. This is the first big lesson of programming: the computer does exactly what you say, not what you mean. Many bugs (mistakes in code) come from that gap.

Why AI and ML engineers use Python

Python is not the fastest language. It became the main language of AI for three practical reasons.

  • The tools already exist. Libraries such as NumPy, Pandas, PyTorch, TensorFlow and scikit-learn are Python-first. Their heavy number crunching is done by fast code written in other languages underneath, and Python is the friendly steering wheel on top.
  • It reads close to English. if accuracy > 0.9: is understandable even before you know the rules. When you are also learning hard ML ideas, you want the language to stay out of your way.
  • Teams share it. Most tutorials, research code and company ML projects use Python, so what you learn here transfers directly to real work.

After that come variations, the common mistakes with their real error messages, two questions to check yourself, and a "Try it" box. You learn more by running and changing code than by reading it, so run every block.
Check yourself
Two lines of a program are swapped and Python shows no error. Does that mean the program is right?
No. Python only checks that each line is valid. It cannot know what you intended. A program can run without errors and still do the wrong thing, so you must always read the output and ask "is this what I wanted?".
What is the difference between "code", "a program" and "running"?
Code is the text you write. A program is a complete list of instructions built from code. Running (executing) is the computer, through the interpreter, carrying those instructions out.

Recap
  • A program is a list of instructions; running it means the computer does them top to bottom.
  • Python's interpreter reads your code line by line and obeys it exactly.
  • The computer does what you write, not what you mean.
  • Python is popular in AI because of its libraries, its readability and its community.

print versus typing a bare value

The main tool for seeing results is print(...). Whatever you put inside the round brackets is shown in the console. Compare a bare calculation with a printed one.

print shows a value; a bare value shows nothing
2 + 3 print(2 + 3) print('2 + 3') print('epoch', 3)
Output
5 2 + 3 epoch 3

What Python does, line by line. (1) Line 1 works out 2 + 3 and gets 5, but nothing tells Python to show it, so the answer is thrown away. In this course's console, a bare value never appears; only print makes output. (2) Line 2 works out 5 and prints it. (3) Line 3 has quotes around 2 + 3. Quotes mean "this is text, do not calculate it", so the characters are printed exactly. (4) Line 4 gives two things separated by a comma. Python prints them with a space between.

💡
Terminal Python is different. If you open a plain Python prompt on your own computer, typing 2 + 3 and pressing Enter does show 5. That convenience belongs to that prompt only. In files, notebooks, scripts and this course's console, use print.

Comments: notes for humans

A comment starts with #. Python ignores everything from the # to the end of the line, so comments are notes to yourself and to the next reader. Good comments explain why, not what the code already says. A useful trick is commenting out: putting # in front of a line to switch it off without deleting it.

Comments are ignored by Python
# Asha trains a photo model. These lines are notes only. print('Training started') # a comment can sit after code too # print('This line is switched off') print('Training finished')
Output
Training started Training finished

Common mistakes (real messages)

Three slips happen to everybody in the first week. Type each one into the console (or copy it) and watch what comes back. The red output is exactly what the console shows. We take error messages apart properly in section 1.5, so for now, notice that Python tells you the kind of error and often a hint.

Forgetting the # on a note
This is my note about the model
What the console shows

Forgetting the brackets (a habit from older Python)
print 'training started'
What the console shows

Forgetting the quotes: Python thinks Hello is a name
print(Hello)
What the console shows

The fixes: put # in front of notes, write print('...') with brackets, and wrap text in quotes. Notice the first message: Python did not say "you forgot a hash". It said invalid syntax, meaning "I cannot read this as a valid instruction". Error messages describe what Python saw, and you work backwards to what you meant.

No. Reloading the page restarts Python and wipes the console's memory. Run the earlier block again first.

1.3 — Variables: Names Stuck on Values

Meet Asha. She is training her cat-versus-dog model, and today it guessed 412 of 500 photos correctly. Here is how she could check her numbers without any new idea.

Numbers with no names
print(412 / 500) print(412 * 100 / 500) print('correct:', 412, 'out of', 500)
Output
0.824 82.4 correct: 412 out of 500

It works, but it is awkward. What is 412? What is 500? If the model improves to 431 tomorrow, Asha must find and change every 412 by hand and hope she misses none. What she wants is to say once "the number of correct guesses is 412", and from then on refer to it by a meaningful name.

That is exactly what a variable is: a name attached to a value. The picture to keep in your head is a sticky note. The value (412) sits somewhere in the computer's memory. The name (correct) is a sticky note you press onto it. Whenever you later write correct, Python follows the note to the value.

You create a variable with the assignment statement, which uses a single equals sign. Read correct = 412 as "stick the name correct on the value 412", never as a maths statement of equality. Python always works out the right side first, then attaches the name on the left.

Asha names her numbers
correct = 412 total = 500 accuracy = correct / total print(accuracy) print(correct, 'of', total)
Output
0.824 412 of 500
The sticky notes after line 3 has run
   name (sticky note)     value (in memory)

   correct  ──────────>  412
   total    ──────────>  500
   accuracy ──────────>  0.824   (412 / 500)

What Python does, line by line. (1) Line 1: the right side is the plain value 412, so Python attaches the note correct to it. (2) Line 2: the note total goes onto 500. (3) Line 3: the right side is correct / total. Python follows the note correct to 412, the note total to 500, divides, gets 0.824, and attaches the new note accuracy to that. (4) Line 4 prints the value behind accuracy. (5) Line 5 prints two values and the words between them.

Reassignment: moving a note

A variable can be attached to a new value at any time. The old value loses that note. This is how a training loop keeps track of "the current epoch": the same name, a new value each time. A very common shape is epoch = epoch + 1. It looks impossible as maths, but as an instruction it is clear: work out the right side first (current epoch plus one), then move the note epoch onto the answer.

Moving a note: reassignment
epoch = 1 print('epoch is', epoch) epoch = 2 print('epoch is', epoch) epoch = epoch + 1 print('epoch is', epoch)
Output
epoch is 1 epoch is 2 epoch is 3

Two names, one value

More than one note can be stuck on the same value. Copying with = does not duplicate the value; it presses a second note onto it. Moving one note afterwards leaves the other where it was. The word is asks "are these two names on the very same value?".

Two sticky notes on one value
best_loss = 0.31 latest_loss = best_loss print(best_loss, latest_loss, best_loss is latest_loss) best_loss = 0.25 print(best_loss, latest_loss, best_loss is latest_loss)
Output
0.31 0.31 True 0.25 0.31 False
Before and after moving one note
   after line 2:                        after line 4:
   best_loss   ──┐                      best_loss   ────>  0.25
                 ├──>  0.31
   latest_loss ──┘                      latest_loss ────>  0.31

With plain numbers and text this never surprises you, because these values cannot be changed in place. Later, in Chapter 4, you will meet lists, where two names on one list do need care. The sticky-note picture will still be your guide.

Rules for good names

A name may contain letters, digits and underscores, but it cannot start with a digit, cannot contain spaces or dashes, and cannot be a word Python already uses (if, for, True and a few more). Names are case-sensitive: loss and Loss are two different notes. The convention in Python is snake_case: lowercase words joined by underscores, such as learning_rate. Choose names that explain themselves. val_loss tells the next reader far more than x2.

Common mistakes (real messages)

Using a name that was never created (a typo)
loss = 0.2341 print(los)
What the console shows
NameError: name 'los' is not defined. Did you mean: 'loss'?
A space inside a name
learning rate = 0.001
What the console shows
SyntaxError: invalid syntax
Starting a name with a digit
2nd_try = 0.9
What the console shows
SyntaxError: invalid decimal literal

The first is a NameError: Python followed the note los and found nothing there, because the note is called loss. Python even guesses your intention ("Did you mean: 'loss'?"). Typos and wrong capital letters cause most NameErrors. The other two are SyntaxErrors: the name itself breaks the spelling rules, so Python cannot even read the line. The fix is learning_rate and second_try. Section 1.5 shows how to read these messages properly.

Here is the ML-flavoured set of variables Asha will use through the chapter. Notice that each variable holds a different kind of value, and that type(...) tells you which kind. Python decides the kind from the value itself, so you never declare it in advance (this is called dynamic typing).

Asha's training run: five variables, five kinds of value
model_name = 'ResNet50' # text: the name of the model epoch = 1 # whole number: which pass over the data loss = 0.2341 # decimal: how wrong the model is now accuracy = 0.9423 # decimal: the fraction it gets right is_training = True # yes/no flag print(type(model_name)) print(type(epoch)) print(type(loss)) print(type(accuracy)) print(type(is_training))
Output
<class 'str'> <class 'int'> <class 'float'> <class 'float'> <class 'bool'>

In everyday terms: an epoch is one full pass through all your practice examples, like reading your whole stack of flashcards once. The loss is a score of how wrong the model currently is, like golf: lower is better. Accuracy is the share of guesses that were right. You will use these words all course, and this table of notes is all they are.

Check yourself
After a = 10 then b = a then a = 99, what is b?
10. Line 2 stuck a second note on the value 10. Line 3 moved only the note a to 99. The note b stayed on 10.
Why is epoch = epoch + 1 not a contradiction?
The = sign means "attach the name", not "equals". Python computes the right side first using the current value, then moves the note onto the result.
Try it. In the "Asha names her numbers" block, change correct to 431 and run again. Only one line changed, yet every printed result updated. Then misspell total as totl on line 3 and read the error you get.
Recap
  • A variable is a name attached to a value, like a sticky note. = means "attach", and the right side is worked out first.
  • You can reassign (move the note) and give one value two names.
  • Names: letters, digits, underscores; no spaces; no leading digit; case matters; use snake_case.
  • A misspelled name gives a NameError; a badly spelled name gives a SyntaxError.
1.4 — Types: Why 5 and "5" Are Not the Same Thing

Here is a puzzle. Asha adds two fives twice. She writes the digit 5 the same way both times, and gets two different answers.

The same digits, two different answers
print(5 + 5) print('5' + '5')
Output
10 55

The first line printed 10. The second printed 55. Nothing is broken. The difference is the quotes, and understanding why is the most important idea in this chapter. Every value in Python has a type: the kind of thing it is. The kind decides what you can do with it. Think of a kitchen. You can add two spoonfuls of sugar together and get a bigger amount, but if you have two labels reading "5" you can only stick them side by side. Numbers get added. Text gets glued.

Python has four basic types you will use constantly.

int
Whole numbers. No decimal point. Short for integer.
epoch = 50
batch_size = 32
num_layers = 12
Use for counting things: epochs, layers, samples
float
Decimal numbers. Always has a point.
lr = 0.001
loss = 0.2341
dropout = 0.5
Use for measuring things: loss, accuracy, weights
str
Text, short for string (a string of characters). Always in quotes, single or double.
model = 'BERT'
path = '/models/v2'
label = "cat"
Use for names: file paths, class labels, model names
bool
Only True or False, with a capital first letter. Named after the mathematician George Boole.
is_training = True
verbose = False
use_gpu = True
Use for yes/no flags and switches
The same characters, two different things
      5                               '5'
   ┌───────┐                          ┌───────┐
   │   5   │                          │  "5"  │
   └───────┘                          └───────┘
   type: int                          type: str
   a quantity to count with           a piece of text, like a key
   + means ADD                        + means GLUE
   5 + 5  ->  10                      '5' + '5'  ->  '55'
The four types, and 50 versus '50'
epochs = 50 # int learning_rate = 0.001 # float model_name = 'ResNet50' # str use_gpu = True # bool print(epochs, type(epochs)) print(learning_rate, type(learning_rate)) print(model_name, type(model_name)) print(use_gpu, type(use_gpu)) print(50 == '50')
Output
50 <class 'int'> 0.001 <class 'float'> ResNet50 <class 'str'> True <class 'bool'> False

What Python does, line by line. Lines 1 to 4 attach four notes to four values, and Python decides each type from how the value is written: no point means int, a point means float, quotes mean str, and the exact words True or False mean bool. Lines 5 to 8 print each value and then its type. The last line asks "is the number 50 equal to the text '50'?". The double equals sign == means compare and gives a bool. The answer is False, because a quantity and a piece of text are different things, even when they look alike.

Variations, one change at a time

Adding a point changes the type: 5 is an int but 5.0 is a float. Quotes can be single or double. Pick one style and keep it, but use the other when the text contains an apostrophe. And the two operators + and * behave differently on text.

One character changes the type
print(type(5), type(5.0), type('5')) print('cat', "cat", "it's fine") print(5 * 3) print('5' * 3) print(3 > 2, type(3 > 2))
Output
<class 'int'> <class 'float'> <class 'str'> cat cat it's fine 15 555 True <class 'bool'>

Notice that '5' * 3 repeats the text three times, giving 555, while 5 * 3 multiplies. Also notice that a comparison like 3 > 2 produces a bool. You will use those True/False answers to make decisions in Chapter 2.

Common mistake: a lowercase boolean

Writing true instead of True
use_gpu = true print(use_gpu)
What the console shows
NameError: name 'true' is not defined. Did you mean: 'True'?

Python only recognises the exact words True and False. When you write true, Python reads it as a name, looks for a sticky note called true, and finds none. The message says exactly that. The fix is the capital letter: use_gpu = True.

Check yourself
What type is each? 7, 7.0, '7', False
int, float, str, bool.
Which type would you choose to store an accuracy of 0.9423, and why?
float. It is a measurement with a fractional part. An int would lose the decimals, and a str could not be used in calculations.
Try it. In the console, print type(True), type('True') and type(1 == 1). Predict each answer before you press Run.
Recap
  • Every value has a type that decides what you can do with it: int (whole), float (decimal), str (text), bool (True/False).
  • 5 is a number and '5' is text: + adds numbers but glues text.
  • type(x) tells you the kind; == compares and gives a bool.
  • Python only knows True and False with capital letters.
1.5 — Reading Your First Error Messages

Sooner or later, red text will appear. Every programmer sees it every day, and the beginners who progress fastest are the ones who learn to read it instead of fearing it. An error message is Python's honest report of what it could not do. It is not a judgement of you. It says what kind of problem occurred, where, and often what to try.

Let us cause a real one on purpose. This block has three lines, and the third contains a typo.

An error on line 3
epochs = 10 loss = 0.5 print(los)
The full report Python writes (real run)
Traceback (most recent call last): File "<exec>", line 3, in <module> NameError: name 'los' is not defined. Did you mean: 'loss'?

The course console shows only the last line of this report, which is the most useful one. Python itself writes the whole report, and you will see it in other tools. Read it from the bottom up.

  • The last line is the diagnosis. NameError: name 'los' is not defined. The word before the colon is the kind of error. The rest is the detail. Here: "I looked for a name called los and there is none."
  • The line above it says where. line 3 is the line number, counted from 1 at the top of your code. Go to that line first.
  • The first line is a header. Traceback (most recent call last) only announces "a report follows". In bigger programs, the lines in between list the chain of steps that led to the problem.

One more rule: an error stops the program right there. Everything before the bad line has already run. Everything after it never runs.

Earlier lines run, later lines never do
print('Step 1 done') print(missing_step) print('Step 3 done')
What the console shows
Step 1 done NameError: name 'missing_step' is not defined

Now meet the four errors you will see most in your first weeks. For each one, the block shows a real run.

SyntaxError: Python cannot read the line

The grammar is wrong: a missing bracket, quote or colon. Python points a caret ^ at the spot where it got confused. The real cause is often right before the caret.

A bracket that never closes
loss = 0.2341 print('Loss is', loss
The full report Python writes (real run)
Traceback (most recent call last): File "<exec>", line 2 print('Loss is', loss ^ SyntaxError: '(' was never closed

The message says '(' was never closed. Python is telling you which bracket to look for. The fix is to add the missing ).

TypeError: the wrong kind of value

The line is valid grammar, but you asked a value to do something its type cannot do. This is 1.4 coming back: adding a number and text.

Adding a number and text
epochs_done = 5 print(epochs_done + '5')
The full report Python writes (real run)
Traceback (most recent call last): File "<exec>", line 2, in <module> TypeError: unsupported operand type(s) for +: 'int' and 'str'

Read it as: "the plus sign does not know how to combine an int with a str". Python refuses to guess whether you meant 10 or 55. You decide: convert the text to a number, or the number to text. Section 1.6 covers exactly how.

The fix: choose what you mean
epochs_done = 5 print(epochs_done + int('5')) # numbers: 10 print(str(epochs_done) + '5') # text: 55
Output
10 55

ZeroDivisionError: the maths is impossible

Dividing by zero
correct = 412 samples = 0 print(correct / samples)
The full report Python writes (real run)
Traceback (most recent call last): File "<exec>", line 3, in <module> ZeroDivisionError: division by zero

Dividing by zero has no answer, in Python or in mathematics. This often happens when a dataset turns out to be empty, so samples is 0. The fix is to find out why the divisor is zero, not to hide the error.

  • Read an error from the bottom up: the last line names the kind and the detail; the line above gives the line number.
  • An error stops the program: earlier lines have run, later lines never do.

1.6 — Type Conversion: Turning Text into Numbers (and Back)

Asha's training script writes one line per epoch into a log file, and tomorrow she wants to read the loss back and do maths on it. A file, however, contains only text. A CSV file (comma-separated values, a simple table stored as text) does not remember which columns were numbers. When Python reads it, every value arrives as a string, even the ones that look like numbers. This surprises almost every beginner, and it is one of the most common bugs in real data projects. Watch it happen.

A number that arrived as text
loss_text = '0.2341' print(loss_text + 1)
What the console shows
TypeError: can only concatenate str (not "int") to str

This is also a TypeError, but the message differs from the one in section 1.5, because now the text is on the left: can only concatenate str (not "int") to str. Concatenate is the technical word for gluing text. Python is saying "on the left I have text, so + means glue, and you gave me a number to glue". The cure is to convert the value: build a new value of the type you need.

Four conversion functions do this, and each is named after its target type: int(x), float(x), str(x) and bool(x). They work like a currency exchange counter. You hand over a value and get back an equivalent value in the other form. The original is untouched, and the exchange is not always possible, as you will see.

Converting text to numbers
loss_text = '0.2341' # from the log file: text epoch_text = '7' # text loss = float(loss_text) # a real decimal now epoch = int(epoch_text) # a real whole number now print(loss + 1) print(epoch * 2) print(type(loss_text), type(loss))
Output

What Python does, line by line. (1) and (2) create two text values. (3) float(loss_text) reads the characters 0.2341 and builds a decimal number, then the note loss is attached to it. (4) int(epoch_text) does the same for the whole number. (5) and (6) now work as ordinary arithmetic, because these are numbers. (7) shows that the original loss_text is still a str: conversion made a new value.

The sad path: conversions that are impossible

A conversion works only if the text really looks like the target type. The error for a bad conversion is a new one, a ValueError: the type was acceptable (text can be converted), but this particular content could not be. Both of these are very common when files are messy.

int() refuses a decimal string
rate_text = '3.9' print(int(rate_text))
What the console shows
ValueError: invalid literal for int() with base 10: '3.9'
float() refuses a comma decimal
score_text = '94,5' print(float(score_text))
What the console shows

The first message quotes your text back to you: '3.9'. The function int only accepts text that is a whole number, and 3.9 has a point. The fix is a two-step conversion: first make the decimal (float), then drop its fractional part (int). The second message shows a European-style decimal comma, which Python does not read. It would need cleaning first (a job for the string tools in section 1.10).

Which conversions work

Study the middle lines. int throws the fraction away, so 3.9 becomes 3 and -3.9 becomes -3. That is truncation (cutting off). If you want the nearest whole number, use round(), which we look at again in section 1.8.

Converting to text, and the truthiness of values

str(x) turns anything into its printable text, which lets you glue a number into a sentence. bool(x) answers "does Python consider this value empty or zero?". These rules are called truthiness: zero and empty things are False, everything else is True.

The trap on the sixth line matters. 'False' is a non-empty piece of text, so bool('False') is True. Python does not read the meaning of your text, only whether it is empty. This trips people up when they read a "yes/no" column from a file.

1.7 — Operators: Doing Maths and Making Comparisons

Asha's dataset has 1000 photos, and her training code feeds them to the model in small groups called batches of 32 photos at a time (like dealing cards a handful at a time instead of all at once). She needs to know two things: how many full batches there are, and how many photos are left over for a final short batch. Long division on paper gives 31 full batches and a remainder of 8. Python has symbols for exactly those steps.

An operator is a symbol that tells Python to combine or compare values, and the values it works on are called operands. In 7 + 2, the plus is the operator and 7 and 2 are the operands. Here is the full set of arithmetic operators, with the ML places you will meet them.

The order of operations

Python follows the same order as school maths: ** first, then *, /, // and %, then + and -. Brackets always win. When in doubt, add brackets. They cost nothing and make your intention clear to the next reader.

Precedence and brackets

Output

Squares and square roots

The power operator does two jobs in ML. error ** 2 squares a number. x ** 0.5 takes the square root, because raising to the power one half is the same thing. Squaring makes every error positive, so a guess that is too low and a guess that is too high both count as "wrong".

Your first ML formula: mean squared error
# Asha's model guessed 0.8, 0.3, 0.9 for photos whose true labels are 1, 0, 1. p1, a1 = 0.8, 1.0 # predicted, actual (two names set at once) p2, a2 = 0.3, 0.0 p3, a3 = 0.9, 1.0 squared_errors = (p1 - a1) ** 2 + (p2 - a2) ** 2 + (p3 - a3) ** 2 mse = squared_errors / 3 # the mean: total divided by how many rmse = mse ** 0.5 # square root brings us back to the original units print(f'MSE: {mse:.6f}') print(f'RMSE: {rmse:.6f}')
Output
MSE: 0.046667 RMSE: 0.216025

In plain words, MSE (mean squared error) is: for each guess, measure how far off it was, square that distance, then average over all guesses. The smaller the number, the better the model. RMSE is the square root of that, which puts it back on the same scale as the original values. You have now written a real loss function with nothing but Chapter 1 tools. The f'...{mse:.6f}' part is an f-string, which section 1.11 explains fully.

1.8 — Integer and Float Pitfalls: Why 0.1 + 0.2 Is Not 0.3

Numbers on a computer do not always behave like numbers on paper. Ask Python a sum a child could do.

A sum that looks wrong
print(0.1 + 0.2) print(0.1 + 0.2 == 0.3) print(412 / 500 * 100)
Output
0.30000000000000004 False 82.39999999999999

This is not a bug in Python. Computers store decimals in binary (ones and zeros). Some simple decimal fractions, like one tenth, cannot be written exactly in binary, in the same way that one third cannot be written exactly in decimal (0.3333...). The computer keeps the closest value it can, and tiny leftovers show up in the sixteenth digit or so. Every programming language that uses standard floats does this.

The practical rules are short. First, never test floats for exact equality with ==. Ask instead whether two values are very close. Second, when you show a float, format or round it. Third, this error is tiny and harmless for ML calculations, so do not panic when you see a long tail of digits.

Compare with a tolerance, and round for display
a = 0.1 + 0.2 b = 0.3 print(a == b) # exact test: False print(abs(a - b) < 1e-9) # "very close" test: True print(round(412 / 500 * 100, 2)) # 82.4 print(f'{0.1 + 0.2:.2f}') # formatted for people: 0.30
Output
False True 82.4 0.30

abs() gives the size of a number without its sign (abs(-0.2) is 0.2), so abs(a - b) is "how far apart are they, ignoring direction". The notation 1e-9 means 1 times ten to the power minus nine, which is 0.000000001. If the gap is smaller than that, we treat the two numbers as equal.

Division always gives a float

Even when the answer is a whole number, / returns a float. Mixing an int and a float in one calculation also gives a float. If you need a whole number back, use // or convert with int().

Which operations give which type
print(10 / 2, type(10 / 2)) # float, even though it divides evenly print(10 // 2, type(10 // 2)) # int print(7 // 2, 7 / 2) # 3 and 3.5 print(3 + 0.5, type(3 + 0.5)) # int + float -> float print(2 ** -1, 2 ** 0.5) # negative and fractional powers
Output
5.0 <class 'float'> 5 <class 'int'> 3 3.5 3.5 <class 'float'> 0.5 1.4142135623730951

Floor division with negatives, and rounding

The name floor division is literal: // rounds down to the next lower whole number. For positive numbers that looks like chopping the fraction, but for negative numbers "down" means further from zero, so -7 // 2 is -4, not -3. This differs from int(), which always moves toward zero. And round() sends halves to the nearest even whole number, a rule called banker's rounding, so round(2.5) is 2 and round(3.5) is 4.

Floor, truncate and round side by side
print(-7 // 2, int(-7 / 2)) # -4 versus -3 print(-7 % 3, 7 % 2) # remainder is never negative here: 2 and 1 print(round(2.5), round(3.5)) # halves go to the even neighbour print(round(0.125, 2), round(2.675, 2))
Output
-4 -3 2 1 2 4 0.12 2.67

The last line shows round(2.675, 2) giving 2.67, not the 2.68 you might expect. The float behind 2.675 is actually a hair below it, so it rounds down. The floating-point effect from earlier is at work again. When you need precise decimals (for money, say), later chapters introduce tools built for that. For ML metrics, round only when you display a number, never in the middle of a calculation.

1.9 — Strings Up Close: Indexing, Slicing and Immutability

Asha keeps her experiments in text names like 'ResNet50'. Sometimes she needs to look inside a name: its first letter, the last two characters, the number at the end. So far a string has been a single lump. To reach inside it, you need to know how Python lays it out.

A string is a row of characters (letters, digits, spaces and symbols), and every character sits in a numbered seat, like seats in a cinema row. The one strange rule is that the numbering starts at 0, not 1. The number of a seat is called its index. You read a character with square brackets: name[0] is the first one. A helpful way to think of it: the index counts how many characters you skip from the start. To get the first character you skip none.

The string 'Python' and its seats
   character:    P     y     t     h     o     n
   index:        0     1     2     3     4     5
   from the end: -6    -5    -4    -3    -2    -1

   s[0:3] = 'Pyt'   (starts at seat 0, stops BEFORE seat 3)
Reading single characters
s = 'Python' print(s[0]) # first character print(s[5]) # last character print(s[-1]) # negative index counts from the end print(s[-2]) print(len(s)) # how many characters
Output
P n n o 6

What Python does, line by line. (1) Attach the note s to the six-character text. (2) Seat 0 holds P. (3) Seat 5 holds n. (4) A negative index counts from the right end, so -1 is always the last character. (5) len(s) counts the characters and gives 6. Notice that the last valid index is one less than the length, because counting started at 0.

Slicing: taking a piece

A slice takes a stretch of characters: s[start:stop]. It begins at the start seat and stops right before the stop seat (the stop seat itself is left out). Leave a number out and Python fills in the edge: no start means the beginning, no stop means the end. A third number is the step, the gap between characters taken.

Slices of 'Python for ML'
s = 'Python for ML' print(s[0:6]) # seats 0 to 5 print(s[:6]) # same thing: start left out print(s[7:]) # from seat 7 to the end print(s[-2:]) # the last two characters print(s[::2]) # every second character print(s[::-1]) # a step of -1 walks backwards print(len(s))
Output
Python Python for ML ML Pto o L LM rof nohtyP 13

A slice never raises an error for going past the end; it quietly gives what exists. A single index is stricter. Asking for a seat that does not exist stops the program.

Asking for a seat that does not exist
s = 'Python' print(s[6])
What the console shows
IndexError: string index out of range

This is an IndexError. The string has seats 0 to 5, so seat 6 is out of range. It is the classic "off by one" mistake that comes from counting from 1 instead of 0. The fix is s[5] or s[-1].

Immutability: strings cannot be edited in place

You can read any seat, but you cannot change one. A string is immutable, which means "cannot be changed after it is made". Every string operation gives you a new string and leaves the old one alone.

Trying to overwrite one character
s = 'Python' s[0] = 'J'
What the console shows
TypeError: 'str' object does not support item assignment
The right way: build a new string
s = 'Python' t = 'J' + s[1:] # glue a new first letter onto the rest u = s.replace('P', 'J') # a method that returns a new string print(t, u) print(s) # the original is unchanged print('=' * 20) # repeating text print('Py' in s, 'py' in s) # membership test; capitals matter
Output
Jython Jython Python ==================== True False

The error 'str' object does not support item assignment means "you tried to put something into a seat of a string, and strings do not allow that". The fix is to make a new string, as the block shows. Also notice '=' * 20, a tidy way to draw a border line, and in, which checks whether a piece of text appears inside another. Capitals count: 'py' in s is False.

A sneak preview: lists use the same seats

Many values in ML are several numbers in a row, such as a model's predictions. A list holds several values in square brackets, and it uses the very same seat numbers (Chapter 4 covers lists fully).

A list of predictions, read by index
predictions = [0.8, 0.3, 0.9] print(predictions[0]) print(predictions[-1]) print(len(predictions)) print(abs(predictions[1] - 1.0)) # abs() drops the minus sign
Output
0.8 0.9 3 0.7

'y', 'h' and 'yth'. The slice takes seats 1, 2 and 3, and stops before seat 4.

Recap
  • A string is a row of characters; the first seat is index 0, and -1 is the last.
  • s[a:b] takes seats a up to (not including) b; a third number sets the step.
  • A bad single index gives IndexError; a slice never does.
  • Strings are immutable: build a new one instead of editing a seat.
1.10 — String Tools: Cleaning, Splitting, Joining

Real text is messy. Labels arrive with stray spaces, odd capitals and extra punctuation, and a model treats 'Cat', 'cat ' and 'CAT' as three different things. Before any text reaches a model, it is cleaned. Python gives every string a built-in toolbox for this.

A tool that belongs to a value is called a method. You use it with a dot: text.lower() means "text, please give me a lowercase copy of yourself". Brackets follow the name, even when they are empty. Because strings are immutable, every method returns a new string. Here is a messy line being cleaned one step at a time.

Cleaning a messy line, one method at a time
raw = ' The QUICK Brown FOX!!! ' step1 = raw.strip() # remove spaces at both ends step2 = step1.lower() # all lowercase step3 = step2.replace('!', '') # delete a character print(repr(raw)) # repr shows the quotes and spaces print(repr(step1)) print(step2) print(step3) print(raw.strip().lower().replace('!', '')) # chained in one line
Output
' The QUICK Brown FOX!!! ' 'The QUICK Brown FOX!!!' the quick brown fox!!! the quick brown fox the quick brown fox

What Python does, line by line. (1) raw has two spaces at each end. (2) strip() returns a copy without them. (3) lower() returns a lowercase copy of that. (4) replace('!', '') swaps every exclamation mark for nothing, deleting them. Each step feeds the next. The last line does all three in a row, called chaining: each method works on the result of the one before it. Note that raw itself never changed.

Finding and testing

Looking for pieces of text
text = 'Python for ML' print(text.find('for')) # the seat where 'for' starts print(text.find('xyz')) # -1 means "not found" print(text.count('o')) # how many times print(text.startswith('Py'), text.endswith('ML')) print(text.upper(), len(text))
Output
7 -1 2 True True PYTHON FOR ML 13

Splitting and joining

split() cuts a string into pieces and gives you a list of them. With no argument it cuts at whitespace; with an argument such as ',' it cuts at every comma, which is exactly how a CSV line becomes separate values. join() is the reverse: ', '.join(pieces) glues a list of strings together with the given text between them. Splitting text into words is the very first step of how language models read.

split and join: one line of a log file
line = '7,0.2341,0.9423' # epoch, loss, accuracy parts = line.split(',') print(parts) print(len(parts), type(parts[1])) # still text! loss = float(parts[1]) print(loss * 2) print(' | '.join(parts)) print('the quick brown fox'.split()) print(float('94,5'.replace(',', '.'))) # fixing the decimal comma from 1.6
Output
['7', '0.2341', '0.9423'] 3 <class 'str'> 0.4682 7 | 0.2341 | 0.9423 ['the', 'quick', 'brown', 'fox'] 94.5

Escapes, raw strings and multi-line text

Inside quotes, a backslash starts an escape: \n means "new line" and \t means "tab". That is a problem for Windows file paths such as C:\models\new, where \n would silently become a line break. A raw string, with an r before the quote, switches escapes off. Text that spans several lines goes between triple quotes.

Escapes, raw strings and triple quotes
print('line one\nline two') # \n is a new line print(r'C:\models\new') # raw: backslashes kept as typed report = """Training Report ---------------- Epochs: 50""" print(report)
Output

Common mistakes

A misspelled method name

What the console shows

An AttributeError means "this value has no such tool". Here the string has upper but no uper. Check spelling and capitals, and remember that Python is case-sensitive. The second common slip is quiet: writing text.strip() on its own line and expecting text to change. It does not. Attach the result: text = text.strip().

  • Use r'...' for backslash paths and """...""" for multi-line text.
1.11 — F-strings: Putting Values into Sentences

After each epoch, Asha wants a progress line in her log. With only what you know so far, she has to convert every number to text and glue the pieces together.

The clumsy way: str() and +
epoch = 15 loss = 0.23412738 accuracy = 0.9423 print('Epoch ' + str(epoch) + ': loss ' + str(loss) + ', accuracy ' + str(accuracy))
Output
Epoch 15: loss 0.23412738, accuracy 0.9423

It works, but look at the problems. There are many quotes and plus signs to get right, a missed space is easy to make, and the loss prints with eight digits, which is far too many for a log. There is a better tool: the f-string (the "f" stands for formatted). It is a text template with holes. You write the sentence normally, put a name inside curly braces where a value belongs, and put the letter f right before the opening quote. Python fills each hole with the current value.

Think of a form letter: "Dear ___, your order ___ has shipped." The blanks are the braces. And because Python fills them, you never call str() yourself.

The smallest f-string
name = 'Asha' epoch = 15 print(f'Hello, {name}!') print(f'Epoch {epoch} finished') print(f'Next epoch is {epoch + 1}')
Output
Hello, Asha! Epoch 15 finished Next epoch is 16

What Python does, line by line. (3) Sees the f in front of the quote, so it scans the text for braces. It finds {name}, looks up the note name, and puts Asha in the hole. (4) The same with epoch: the number is converted to text automatically. (5) Anything that produces a value is allowed inside the braces, including a small calculation such as epoch + 1.

Controlling how a number looks

After the value you may add a colon and a format spec, a short code saying how to display it. {loss:.4f} means "show loss as a float with 4 digits after the point". This changes only the display, not the number itself.

Width and alignment: tidy columns

Width and alignment make output line up like a table. < pads on the right (left-aligned), > pads on the left (right-aligned), and ^ centres.

A small table and a conditional
accuracy, loss = 0.9423, 0.2341 print(f"{'Metric':<10}{'Value':>10}") print(f"{'accuracy':<10}{accuracy:>10.4f}") print(f"{'loss':<10}{loss:>10.4f}") print(f"[{'centre':^12}]") status = 'GOOD' if accuracy > 0.9 else 'NEEDS WORK' print(f'Status: {status}')
Output
Metric Value accuracy 0.9423 loss 0.2341 [ centre ] Status: GOOD

The 'GOOD' if accuracy > 0.9 else 'NEEDS WORK' line is a conditional expression: value-if-true, then if a yes/no question, then else value-if-false. Python checks whether accuracy > 0.9 is True and picks the matching value. Chapter 2 develops decisions much further. Here, treat it as a two-way choice in one line.

1.12 — How to Get Unstuck

Every programmer, on every project, spends a large share of the day stuck. Being stuck is not a sign that you are bad at this. It is the normal working state, and there is a skill to getting out of it. Learn the routine now and you will save hours later.

Asha wants the average of her model's accuracy on two test sets, 0.8 and 0.6. The answer should be 0.7. Here is her attempt.

The code runs, but the answer is wrong
first = 0.8 second = 0.6 average = first + second / 2 print(average)
Output
1.1

No error message appeared, so there is nothing to read. This is the hardest kind of bug, because Python did exactly what was written. The technique is debugging by printing: show the intermediate pieces, and compare each one with what you expected.

Print the pieces to find the bad step
first = 0.8 second = 0.6 print('second / 2 =', second / 2) # 0.3, as expected print('first + that =', first + second / 2) # 1.1: the division ran first average = (first + second) / 2 # brackets force the addition first print('fixed:', average)
Output
second / 2 = 0.3 first + that = 1.1 fixed: 0.7

The second print revealed it: division goes before addition (section 1.7), so only second was halved. Brackets fixed it. Notice how printing turned a vague feeling ("the number is wrong") into a specific, checkable fact.

The get-unstuck loop
   1. Is there an error message?
      YES: read the LAST line, go to that line number,
           check names, types and brackets
      NO : print values and types, find the FIRST
           one that is not what you expected
   2. Change ONE thing.
   3. Run again and compare.
      Fixed? Stop.   Not fixed? Back to 1.

A checklist to work through

  • Read the last line of the error and name its kind: NameError, SyntaxError, TypeError, ValueError, IndexError, ZeroDivisionError. Section 1.5 has the meanings.
  • Go to the line number and read that line slowly, letter by letter. Most bugs are spelling, capitals, a missing quote or bracket, or = versus ==.
  • Print the values and their types right before the failing line: print(x, type(x)). A number that is really text explains many TypeErrors.
  • Make the problem smaller. Copy the failing line into the console alone with plain numbers. If it works, the trouble is in the values, not the line.
  • Change one thing at a time, then run again. If you change five things and it works, you will not know which one mattered.
  • Check the console's memory. A name may hold an old value from an earlier run, or may not exist because you skipped a block. Reload the page for a clean start and run the blocks in order.
  • Search or ask, with the exact message. Copy the error's last line into a search engine, or into a question to a person or an AI assistant, together with the few lines of code around it.

One more error you will meet: IndentationError

Python cares about spaces at the start of a line. Code that begins at the left edge must stay there unless a later chapter gives it a reason to move. A stray space produces this.

The message says unexpected indent: "this line starts further right than it should". Delete the leading spaces. Chapter 2 explains the cases where indentation is required, and you will then use it on purpose.
