Advanced 4:
Evaluation Beyond Accuracy

You already know how to hold a model to a fair test: split the data, run k-fold cross-validation, compare candidates on a held-out set (ml/ch19, projects/ch33 §33.3–33.4). This chapter assumes all of that is solid and asks a harder question: even with a perfectly honest split, is the metric itself telling you the truth? A model can pass cross-validation and still be miscalibrated, still be silently wrong for one subgroup, still look better only because of an uncontrolled comparison — and once the system under test is an LLM or a RAG pipeline, "accuracy" barely applies at all. We cover calibration, class imbalance, error analysis and experiment design for classical models, then retrieval metrics, faithfulness, hallucination evaluation and the real, documented limits of using an LLM as a judge.

4.1 — Recap and the Real Question: "Good According to What?"

Chapter 19 gave you Pipeline, KFold, cross_val_score and GridSearchCV so a model's reported score is not a lucky accident of one split. Chapter 33 (§33.3–33.4) chained that into a full pipeline: clean data, split, compare candidates honestly with cross-validation, then evaluate the winner once on a held-out set. We are not re-deriving any of that here — if you are shaky on why you fit a scaler on training data only, or what cv=5 actually runs, go back to those chapters first.

This chapter asks a different question. Suppose the split is perfect and the cross-validation is honest. The number you get back — 0.94 accuracy, 0.89 F1, whatever it is — is still just one number, and every single-number summary throws information away. It can hide a model that is confidently wrong, a model that only works for the majority subgroup, a "finding" that was never really tested against a control, or — once the system you are grading is an LLM instead of a classifier — a whole different set of questions that accuracy cannot even ask. Evaluation beyond accuracy means treating the metric itself as something that needs to be interrogated, not just computed.

4.2 — Calibration: Do Your Probabilities Mean Anything?

A classifier's .predict_proba() output looks like a probability, but nothing forces it to behave like one. A model is calibrated if, among all the times it says "70% confident", the outcome actually happens about 70% of the time. This matters anywhere a downstream decision uses the number itself, not just the yes/no call: risk scores that feed a threshold set by a business team, probabilities averaged across an ensemble, or a probability that gets multiplied by a dollar amount to estimate expected loss. A model that is 95% "confident" but right only 70% of the time is not a detail — it is a model that will get trusted more than it has earned.

Reliability diagrams and the Brier score

A reliability diagram buckets predictions into probability bins (0.0–0.1, 0.1–0.2, …) and, within each bin, compares the average predicted probability to the actual observed frequency of the positive class. A perfectly calibrated model has those two numbers equal in every bin. The Brier score is the single-number summary of the same idea: the mean squared error between each predicted probability and the actual 0/1 outcome, mean((p - y) ** 2). Lower is better; 0 is a perfect, fully confident and always-correct model, and 0.25 is what you get from a coin-flip model that always predicts 0.5. Critically, the Brier score rewards BOTH being right and being appropriately confident — a model can have decent accuracy and still have a bad Brier score if its confident predictions are the ones that are wrong.

Brier score, a reliability table, and fixing it with temperature scaling
import numpy as np rng = np.random.default_rng(7) n = 2000 true_score = rng.normal(0, 1.5, n) true_p = 1 / (1 + np.exp(-true_score)) y = (rng.random(n) < true_p).astype(int) raw_logit = true_score * 2.2 model_p = 1 / (1 + np.exp(-raw_logit)) def brier_score(p, y): return np.mean((p - y) ** 2) def reliability_table(p, y, n_bins=10): bins = np.linspace(0, 1, n_bins + 1) rows = [] for lo, hi in zip(bins[:-1], bins[1:]): mask = (p >= lo) & (p < hi) if hi < 1 else (p >= lo) & (p <= hi) if mask.sum() == 0: continue rows.append((f"{lo:.1f}-{hi:.1f}", int(mask.sum()), float(p[mask].mean()), float(y[mask].mean()))) return rows print(f"Brier score (overconfident model): {brier_score(model_p, y):.4f}") for label, count, avg_p, avg_y in reliability_table(model_p, y): print(f" bin {label}: n={count:4d} avg predicted={avg_p:.3f} actual freq={avg_y:.3f}") def apply_temperature(logit, T): return 1 / (1 + np.exp(-logit / T)) Ts = np.linspace(0.5, 4.0, 36) best_T, best_brier = None, 1e9 for T in Ts: p_t = apply_temperature(raw_logit, T) b = brier_score(p_t, y) if b < best_brier: best_brier, best_T = b, T calibrated_p = apply_temperature(raw_logit, best_T) print(f"\nBest temperature found by grid search: {best_T:.2f}") print(f"Brier before calibration: {brier_score(model_p, y):.4f}") print(f"Brier after calibration: {brier_score(calibrated_p, y):.4f}") for label, count, avg_p, avg_y in reliability_table(calibrated_p, y): print(f" bin {label}: n={count:4d} avg predicted={avg_p:.3f} actual freq={avg_y:.3f}")
Brier score (overconfident model): 0.1904 bin 0.0-0.1: n= 537 avg predicted=0.032 actual freq=0.142 bin 0.1-0.2: n= 160 avg predicted=0.147 actual freq=0.319 ... bin 0.9-1.0: n= 478 avg predicted=0.968 actual freq=0.851 Best temperature found by grid search: 2.20 Brier before calibration: 0.1904 Brier after calibration: 0.1754 bin 0.0-0.1: n= 140 avg predicted=0.061 actual freq=0.057 ... bin 0.9-1.0: n= 140 avg predicted=0.939 actual freq=0.943

Notice the pattern before calibration: in the lowest bin the model says "3% likely" but the true rate is 14%, and in the top bin it says "97% likely" against a true rate of 85% — classic overconfidence, common in models with high-magnitude logits (deep nets are especially prone to this). Temperature scaling is the standard production fix: keep the model's raw logit output, but divide it by a single learned scalar T before the sigmoid, then pick T to minimize a calibration loss on a held-out calibration set (here, a small grid search over Brier score stands in for that fit). One number, fit on held-out data, completely reshapes the reliability table without touching which class gets predicted — the ranking of examples, and therefore accuracy and AUC, is unchanged, because scaling every logit by the same constant never reorders them.

ℹ️
In productionscikit-learn's CalibratedClassifierCV automates exactly this (Platt scaling or isotonic regression instead of a hand-rolled grid search), fit on a held-out calibration fold so you are not calibrating against the same data the model was scored on.
4.3 — Class Imbalance: Why Accuracy Lies

Fraud is rare. Churn is rare. The disease you are screening for is rare. In every one of these, a model that never fires at all — that predicts the majority class 100% of the time — can post an accuracy that looks like a success and is actually a model that does nothing. Accuracy treats a false negative on the 5% minority class exactly the same as a false positive on the 95% majority class, which is precisely backwards for most of these problems: missing the rare fraud case is usually the expensive mistake.

The metrics that don't lie the same way

MetricWhat it actually measuresBlind spot
AccuracyFraction of all predictions correctDominated by the majority class; can look great while missing every positive

RecallOf the real positives, how many you caughtSays nothing about how noisy your alerts are
F1Harmonic mean of precision and recallOne number again — hides which of the two is actually the problem
ROC-AUCRanking quality across all thresholds, x-axis is false-positive rateFPR stays small on imbalanced data even when precision collapses — ROC-AUC can look great on a nearly-useless model
PR-AUCRanking quality across all thresholds, x-axis is precision itselfMore honest here, but has no fixed floor to compare against (unlike ROC-AUC's 0.5)
A 6.8%-positive dataset: majority baseline vs plain LR vs class-weighting vs threshold-moving
import numpy as np from sklearn.datasets import make_classification from sklearn.linear_model import LogisticRegression from sklearn.metrics import (accuracy_score, precision_score, recall_score, f1_score, roc_auc_score, average_precision_score) X, y = make_classification(n_samples=2000, n_features=6, n_informative=4, weights=[0.95, 0.05], random_state=13, flip_y=0.01) split = 1500 X_train, X_test = X[:split], X[split:] y_train, y_test = y[:split], y[split:] print(f"Test set positives: {y_test.sum()} / {len(y_test)} ({y_test.mean():.1%})") majority_pred = np.zeros_like(y_test) print(f"\nAlways-predict-majority accuracy: {accuracy_score(y_test, majority_pred):.4f}") print(f"Always-predict-majority recall on the minority class: {recall_score(y_test, majority_pred, zero_division=0):.4f}") plain = LogisticRegression(max_iter=1000).fit(X_train, y_train) plain_pred = plain.predict(X_test) plain_proba = plain.predict_proba(X_test)[:, 1] print(f"\nPlain LogisticRegression accuracy: {accuracy_score(y_test, plain_pred):.4f}") print(f" precision={precision_score(y_test, plain_pred):.3f} recall={recall_score(y_test, plain_pred):.3f} f1={f1_score(y_test, plain_pred):.3f}") print(f" ROC-AUC={roc_auc_score(y_test, plain_proba):.3f} PR-AUC={average_precision_score(y_test, plain_proba):.3f}") balanced = LogisticRegression(max_iter=1000, class_weight="balanced").fit(X_train, y_train) bal_pred = balanced.predict(X_test) bal_proba = balanced.predict_proba(X_test)[:, 1] print(f"\nclass_weight='balanced' accuracy: {accuracy_score(y_test, bal_pred):.4f}") print(f" precision={precision_score(y_test, bal_pred):.3f} recall={recall_score(y_test, bal_pred):.3f} f1={f1_score(y_test, bal_pred):.3f}") print(f" ROC-AUC={roc_auc_score(y_test, bal_proba):.3f} PR-AUC={average_precision_score(y_test, bal_proba):.3f}") # threshold moving on the PLAIN model to hit a target recall target_recall = 0.80 thresholds = np.linspace(0.01, 0.99, 99) best_t = None for t in thresholds: pred_t = (plain_proba >= t).astype(int) r = recall_score(y_test, pred_t, zero_division=0) if r >= target_recall: best_t = t # keep raising threshold while recall target still met -> highest precision at that recall print(f"\nThreshold-moving on the SAME plain model, target recall >= {target_recall:.0%}:") pred_final = (plain_proba >= best_t).astype(int) print(f" chosen threshold={best_t:.2f} precision={precision_score(y_test, pred_final):.3f} recall={recall_score(y_test, pred_final):.3f} f1={f1_score(y_test, pred_final):.3f}")
Test set positives: 34 / 500 (6.8%) Always-predict-majority accuracy: 0.9320 Always-predict-majority recall on the minority class: 0.0000 Plain LogisticRegression accuracy: 0.9620 precision=0.895 recall=0.500 f1=0.642 ROC-AUC=0.954 PR-AUC=0.783 class_weight='balanced' accuracy: 0.8640 precision=0.323 recall=0.912 f1=0.477 ROC-AUC=0.967 PR-AUC=0.777 Threshold-moving on the SAME plain model, target recall >= 80%: chosen threshold=0.09 precision=0.406 recall=0.824 f1=0.544

Read this output slowly. The do-nothing baseline gets 93.2% accuracy and 0% recall — if a stakeholder only ever sees "accuracy: 93%" for either the baseline or the real model, they cannot tell those two models apart, which is the whole problem with accuracy on imbalanced data. The plain model looks strong (96.2% accuracy) but only catches half the real positives. ROC-AUC barely moves between the plain and balanced models (0.954 vs 0.967) because false-positive rate stays tiny either way with this much majority-class data — PR-AUC (0.783 vs 0.777) is the more honest, harder-to-fool lens here because its x-axis is precision, which the imbalance directly punishes.

Three different levers, not three different metrics

Resampling (oversample the minority class, undersample the majority, or synthesize new minority examples with SMOTE) changes what the model trains on. Class-weighting (class_weight="balanced" above) changes the loss function so mistakes on the minority class cost more, without touching the data at all — usually the cheapest lever to try first. Threshold-moving changes neither the data nor the training objective: it trains one plain model, keeps its probability output, and picks a decision threshold to hit a target recall or precision after the fact, as the last block above does. These three are not competing "which metric to use" answers — they are different places in the pipeline to spend the same underlying trade-off, and the right choice depends on whether you can afford to retrain, whether you know your target operating point in advance, and whether you need one threshold or a whole ranked list.

4.4 — Rigorous Error Analysis: Finding the Failure Mode Hiding in the Average

An overall metric is an average, and an average can hide a model that is excellent for most of the population and quietly broken for a slice of it. Error analysis means deliberately slicing your metrics by subgroup — region, device type, a demographic attribute, the data source a record came from, time period, input length — and asking whether performance is uniform, not just whether it is good on average. This is the same discipline as the "what changed" debugging method elsewhere in this course: you don't ask "is the system healthy", you ask "is it EQUALLY healthy everywhere", because the gap between those two questions is where systematic failures live.

One model, sliced by subgroup: the overall number hides a real gap
import numpy as np from sklearn.datasets import make_classification from sklearn.linear_model import LogisticRegression from sklearn.metrics import accuracy_score, recall_score, confusion_matrix rng = np.random.default_rng(4) X, y = make_classification(n_samples=1600, n_features=8, n_informative=5, random_state=21, class_sep=1.3) # a subgroup feature the model never sees directly during training, # but which happens to correlate with a noisy, low-signal region of feature space group = np.where(X[:, 0] > 0.6, "B", "A") split = 1200 X_train, X_test, y_train, y_test = X[:split], X[split:], y[:split], y[split:] group_test = group[split:] # corrupt group-B TRAINING examples with label noise, simulating a systematic # data-quality gap (e.g. group B came from a different, messier data source) noisy_train_group = group[:split] y_train_noisy = y_train.copy() b_mask = noisy_train_group == "B" flip = rng.random(b_mask.sum()) < 0.35 idx = np.where(b_mask)[0][flip] y_train_noisy[idx] = 1 - y_train_noisy[idx] clf = LogisticRegression(max_iter=1000).fit(X_train, y_train_noisy) pred = clf.predict(X_test) print(f"Overall accuracy: {accuracy_score(y_test, pred):.4f}") print(f"Overall recall: {recall_score(y_test, pred):.4f}") print("\nSliced by subgroup:") for g in ["A", "B"]: mask = group_test == g acc = accuracy_score(y_test[mask], pred[mask]) rec = recall_score(y_test[mask], pred[mask], zero_division=0) n = mask.sum() print(f" group {g}: n={n:3d} accuracy={acc:.4f} recall={rec:.4f}") cm_b = confusion_matrix(y_test[group_test == "B"], pred[group_test == "B"]) print(f"\nGroup B confusion matrix [[TN FP] [FN TP]]:\n{cm_b}")
Overall accuracy: 0.7675 Overall recall: 0.7644 Sliced by subgroup: group A: n=229 accuracy=0.8952 recall=0.8814 group B: n=171 accuracy=0.5965 recall=0.6111 Group B confusion matrix [[TN FP] [FN TP]]: [[47 34] [35 55]]

76.75% overall accuracy sounds like a model that is basically working. Sliced by subgroup, group A is at 89.5% and group B is at 59.6% — a 30-point gap that the headline number completely erases. In this toy example the cause is deliberately visible in the code: group B's training labels were corrupted more often, simulating the extremely common real-world case where one subgroup's data came from a messier pipeline, a different collection process, or a smaller sample. The fix is never "make the model better" in the abstract — it is "find out WHY group B is worse" (data quality? underrepresentation? a genuinely harder subpopulation?) and address that specific cause. Error analysis does not end at finding the gap; a full pass also reads a sample of the group's actual mispredictions to look for a pattern (a keyword, a format, a length) rather than stopping at the number.

A subgroup slice needs enough data to trustGroup B here has n=171, plenty for a stable estimate; a slice with n=12 producing a scary-looking accuracy number is usually noise, not a finding — check the sample size before you act on a slice.
4.5 — Experiment Design: Ablations, Confounding, and "Just Try It and See"

"I changed the regularization strength and accuracy went up three points" is not evidence of anything unless you can also answer: compared to what, on the same data, with everything else held fixed? A confound is a second thing that changed alongside the thing you meant to test, so you cannot tell which one caused the effect you observed. The single most common confound in ML experimentation is comparing two runs on different random data splits or random seeds — the "improvement" you see may be entirely explained by which examples happened to land in the test set that time, not by your change at all.

What a clean ablation looks like

A good ablation changes exactly one variable, holds every other variable fixed (same data split, same seed, same preprocessing), and repeats the comparison across enough independent trials (different seeds, in the SAME paired way) to see whether the effect survives the noise. The output is a table with a mean AND a spread, not a single "before" and "after" number.

An uncontrolled comparison vs a controlled ablation, on the same underlying change
import numpy as np from sklearn.datasets import make_classification from sklearn.linear_model import LogisticRegression from sklearn.metrics import accuracy_score def make_split(seed): X, y = make_classification(n_samples=800, n_features=10, n_informative=6, random_state=seed, class_sep=0.9) return X[:600], X[600:], y[:600], y[600:] def score(X_train, X_test, y_train, y_test, C): clf = LogisticRegression(max_iter=1000, C=C).fit(X_train, y_train) return accuracy_score(y_test, clf.predict(X_test)) # UNCONTROLLED "just try it and see": baseline run on seed 0, "improved" run on seed 1 Xtr0, Xte0, ytr0, yte0 = make_split(0) Xtr1, Xte1, ytr1, yte1 = make_split(1) baseline_uncontrolled = score(Xtr0, Xte0, ytr0, yte0, C=1.0) improved_uncontrolled = score(Xtr1, Xte1, ytr1, yte1, C=0.1) print("Uncontrolled comparison (different data draws AND different C):") print(f" baseline (seed 0, C=1.0): {baseline_uncontrolled:.4f}") print(f" 'improved' (seed 1, C=0.1): {improved_uncontrolled:.4f}") print(f" apparent gain: {improved_uncontrolled - baseline_uncontrolled:+.4f}\n") # CONTROLLED ablation: same data draw (same seed), change ONLY C, repeat over several seeds print("Controlled ablation: same seed for both arms, vary ONLY C, across 8 seeds:") gains = [] for seed in range(8): Xtr, Xte, ytr, yte = make_split(seed) base = score(Xtr, Xte, ytr, yte, C=1.0) variant = score(Xtr, Xte, ytr, yte, C=0.1) gains.append(variant - base) print(f" seed {seed}: baseline={base:.4f} variant={variant:.4f} gain={variant-base:+.4f}") gains = np.array(gains) print(f"\nMean gain across matched seeds: {gains.mean():+.4f} (std {gains.std(ddof=1):.4f})") print(f"Seeds where the variant was actually worse: {(gains < 0).sum()} / {len(gains)}")
Uncontrolled comparison (different data draws AND different C): baseline (seed 0, C=1.0): 0.9100 'improved' (seed 1, C=0.1): 0.8600 apparent gain: -0.0500 Controlled ablation: same seed for both arms, vary ONLY C, across 8 seeds: seed 0: baseline=0.9100 variant=0.9050 gain=-0.0050 seed 1: baseline=0.8600 variant=0.8600 gain=+0.0000 ... seed 7: baseline=0.5750 variant=0.5800 gain=+0.0050 Mean gain across matched seeds: +0.0013 (std 0.0035) Seeds where the variant was actually worse: 1 / 8

The uncontrolled comparison reports a 5-point DROP from lowering C — but it changed the data split and the hyperparameter at the same time, so that number could just as easily be "seed 1 was a harder split" as "C=0.1 is worse." The controlled version holds the split fixed within each trial and only varies C, then repeats across 8 independently drawn splits: the true mean effect is roughly zero (+0.0013, std 0.0035), an order of magnitude smaller than the misleading -0.05 the sloppy comparison produced, and its sign even flips on 1 of the 8 seeds. This is the difference between "I tried something and the number went up" and an actual experiment.

"Just try it and see" fails for the same reason a single train/test split can get lucky: one comparison is one sample. A control (the SAME conditions, minus the one change) plus repetition (enough independent trials to see the spread) is what turns "I tried something" into an experiment whose result you can trust, and it is exactly as necessary for a one-line hyperparameter tweak as for a full research ablation study.

4.6 — Evaluating RAG and LLM Systems: A New Set of Failure Modes

Everything above — calibration, imbalance-aware metrics, slicing, controlled comparisons — still applies once the "model" is an LLM or a retrieval-augmented pipeline. But "accuracy" stops being well-defined the moment the output is free text instead of a class label, and a RAG system fails in ways a classifier structurally cannot: it can retrieve the wrong documents, or the right documents and then ignore them, or write a fluent answer that is simply false. Grading it well means grading each stage separately.

Note the ordering of failures: a perfect generator fed the wrong documents will confidently answer the wrong question, so retrieval quality is graded first and separately — a bad final answer with good retrieval metrics is a generation/faithfulness bug, while a bad final answer with bad retrieval metrics is a retrieval bug, and conflating the two wastes debugging time on the wrong stage.

4.7 — Retrieval Metrics: recall@k, MRR, nDCG

recall@k asks: of all the documents that are actually relevant to this query, what fraction appear anywhere in the top k retrieved? It rewards getting relevant material into the context window at all, and does not care about order within the top k. MRR (mean reciprocal rank) looks at only the FIRST relevant result and scores 1/rank — a relevant document at rank 1 scores 1.0, at rank 3 scores 0.33, so MRR rewards getting something good to the top fast, which matters when a generator pays more attention to earlier chunks. nDCG (normalized discounted cumulative gain) generalizes both: every relevant document in the list contributes, but earlier ranks are worth exponentially more, normalized against the best possible ordering of the same relevant set — the one metric here that rewards BOTH "found everything relevant" and "ranked it well".

recall@k, MRR and nDCG on the same four queries
import numpy as np # Each query has a ranked list of retrieved doc ids and a set of doc ids that are # actually relevant (judged by a human or a gold label), exactly the shape a real # retrieval eval harness works with. queries = [ {"q": "capital of Australia", "ranked": ["doc_9", "doc_2", "doc_5", "doc_1", "doc_7"], "relevant": {"doc_5"}}, {"q": "founder of Python", "ranked": ["doc_3", "doc_8", "doc_2", "doc_6", "doc_4"], "relevant": {"doc_3", "doc_6"}}, {"q": "boiling point of water at altitude", "ranked": ["doc_1", "doc_4", "doc_9", "doc_2", "doc_5"], "relevant": {"doc_9"}}, {"q": "who wrote Pride and Prejudice", "ranked": ["doc_7", "doc_2", "doc_1", "doc_3", "doc_5"], "relevant": {"doc_1", "doc_5"}}, ] def recall_at_k(ranked, relevant, k): hit = set(ranked[:k]) & relevant return len(hit) / len(relevant) def reciprocal_rank(ranked, relevant): for i, d in enumerate(ranked, start=1): if d in relevant: return 1.0 / i return 0.0 def dcg_at_k(ranked, relevant, k): return sum(1.0 / np.log2(i + 1) for i, d in enumerate(ranked[:k], start=1) if d in relevant) def ndcg_at_k(ranked, relevant, k): ideal = sum(1.0 / np.log2(i + 1) for i in range(1, min(len(relevant), k) + 1)) if ideal == 0: return 0.0 return dcg_at_k(ranked, relevant, k) / ideal K = 3 recalls, rrs, ndcgs = [], [], [] for item in queries: r = recall_at_k(item["ranked"], item["relevant"], K) rr = reciprocal_rank(item["ranked"], item["relevant"]) nd = ndcg_at_k(item["ranked"], item["relevant"], K) recalls.append(r); rrs.append(rr); ndcgs.append(nd) print(f"{item['q'][:32]:32s} recall@{K}={r:.2f} RR={rr:.2f} nDCG@{K}={nd:.3f}") print(f"\nMean recall@{K}: {np.mean(recalls):.3f}") print(f"MRR: {np.mean(rrs):.3f}") print(f"Mean nDCG@{K}: {np.mean(ndcgs):.3f}")

Neither metric alone tells the full story — which is exactly why a real evaluation harness reports several of these side by side rather than picking one and calling retrieval "solved."

4.8 — Faithfulness and Groundedness: Does the Answer Only Use What Was Retrieved?

A faithful (or grounded) answer only makes claims supported by the retrieved context — it does not matter whether a claim is true in the real world, only whether the system's OWN evidence supports it, because a RAG system that answers correctly from outside knowledge it was never given credit for is not something you can trust to behave the same way next time it lacks that outside knowledge. A cheap, illustrative heuristic: split the answer into sentences and, for each one, measure what fraction of its (non-trivial) words also appear somewhere in the retrieved chunks.

A word-overlap groundedness heuristic, sentence by sentence
import re def tokenize(s): return set(re.findall(r"[a-z0-9]+", s.lower())) def sentence_split(text): return [s.strip() for s in re.split(r"(?<=[.!?])\s+", text.strip()) if s.strip()] def groundedness_score(sentence, context_chunks, stop=frozenset( "the a an is are was were of in on to and or for with as by at from that this it its be".split())): """Heuristic only: fraction of a sentence's non-trivial words that also appear somewhere in the retrieved context. This is NOT a real faithfulness metric — see the discussion after this block for what it misses.""" words = tokenize(sentence) - stop if not words: return 1.0 context_words = set() for c in context_chunks: context_words |= tokenize(c) covered = words & context_words return len(covered) / len(words) retrieved_context = [ "The Eiffel Tower was completed in 1889 for the World's Fair in Paris.", "It stands 330 metres tall and was designed by engineer Gustave Eiffel's company.", ] answer = ( "The Eiffel Tower was completed in 1889 for the World's Fair. " "It is 330 metres tall. " "It was originally intended to be dismantled after 20 years but was kept for radio transmissions." ) THRESHOLD = 0.55 print(f"{'sentence':70s} score flag") for sent in sentence_split(answer): s = groundedness_score(sent, retrieved_context) flag = "UNGROUNDED?" if s < THRESHOLD else "ok" print(f"{sent[:68]:70s} {s:.2f} {flag}")
sentence score flag The Eiffel Tower was completed in 1889 for the World's Fair. 1.00 ok It is 330 metres tall. 1.00 ok It was originally intended to be dismantled after 20 years but was k 0.00 UNGROUNDED?

The first two sentences restate the retrieved chunks and score 1.00. The third sentence introduces a fact (dismantling, radio transmissions) that never appears in the retrieved context at all — correctly flagged, regardless of whether it happens to be historically true, because faithfulness is about what the system's OWN evidence supports, not about the real world.

ℹ️
What a real system uses insteadProduction faithfulness checks use a natural-language-inference (NLI) or entailment model to test whether the retrieved context entails each claim, or an LLM-as-judge prompt asking specifically "is this claim supported by this context, yes/no" per sentence — both catch paraphrase and catch confident-sounding recombination that word overlap misses entirely, at the cost of needing a second model call per claim.
4.9 — Hallucination Evaluation: Why It's Hard

Hallucination is usually defined as a generated claim that is unsupported by, or contradicts, the available evidence (the retrieved context, or the training data for a non-RAG model). It is hard to measure for reasons that stack on top of each other: there is often no single ground-truth document to check every claim against; a claim can be TRUE in the world but unsupported by what was retrieved (still a failure, per 4.8); a model can restate a real fact with one wrong number and sound exactly as confident as when it is fully correct; and cheap proxy metrics built on lexical overlap are fooled by fluent, plausible-sounding recombinations of real words into false claims.

The word-overlap heuristic's blind spot: fooled by vocabulary, not by truth
import re def tokenize(s): return set(re.findall(r"[a-z0-9]+", s.lower())) def groundedness_score(sentence, context_chunks, stop=frozenset( "the a an is are was were of in on to and or for with as by at from that this it its be".split())): words = tokenize(sentence) - stop if not words: return 1.0 context_words = set() for c in context_chunks: context_words |= tokenize(c) covered = words & context_words return len(covered) / len(words) retrieved_context = [ "The Eiffel Tower was completed in 1889 for the World's Fair in Paris.", "It stands 330 metres tall and was designed by engineer Gustave Eiffel's company.", ] # a hallucinated sentence built almost entirely from words that DO appear in the # context, but that recombines them into a claim the context never makes hallucinated = "The Eiffel Tower was completed in Paris by Gustave in 330 days for the World's Fair." true_but_rephrased = "Paris hosted the World's Fair the same year the tower was finished, in 1889." for label, sent in [("hallucinated but high word-overlap", hallucinated), ("true but paraphrased, lower overlap", true_but_rephrased)]: s = groundedness_score(sent, retrieved_context) print(f"{label:38s} score={s:.2f} -> {sent}")
hallucinated but high word-overlap score=0.90 -> The Eiffel Tower was completed in Paris by Gustave in 330 days for the World's Fair. true but paraphrased, lower overlap score=0.60 -> Paris hosted the World's Fair the same year the tower was finished, in 1889.

The hallucinated sentence reuses almost every word from the retrieved context ("Eiffel Tower", "Paris", "Gustave", "330", "World's Fair") but recombines them into a false claim (built "in 330 days", not "330 metres tall") and scores 0.90 — it LOOKS grounded to a lexical-overlap check. The true, faithful sentence below it uses different words to say something the context actually supports, and scores lower for it. This is the general shape of every cheap hallucination proxy: word/n-gram overlap, embedding similarity to the context, and even naive NLI models can all be fooled by surface-level resemblance in one direction and unfairly penalize honest paraphrase in the other. The more reliable (and more expensive) approaches decompose the answer into atomic claims and check each one against evidence individually, or run the same query multiple times and treat claims that are NOT consistent across samples as suspect (self-consistency checking) — both catch more than lexical overlap, and both cost real inference-time compute, so no hallucination metric is free.

4.10 — LLM-as-Judge: How It Works, and Its Real, Documented Failure Modes

LLM-as-judge means using a strong LLM to score or compare outputs instead of (or alongside) human raters: pointwise scoring ("rate this answer 1-10 against this rubric"), or pairwise comparison ("which of these two answers is better, A or B"). It scales far past what humans can rate and correlates reasonably well with human judgment on average — which is exactly why it is worth being precise about where it is known to fail, instead of either trusting it blindly or dismissing it entirely.

Three well-documented biases

BiasWhat happensCommon mitigation
Position biasIn pairwise comparison, the judge favors whichever answer is shown in a particular slot (often first), independent of contentScore BOTH orderings and require agreement, or average the two
Verbosity biasLonger answers score higher even when they are not more correct or more helpfulExplicitly instruct the judge to ignore length, or length-normalize / penalize in the rubric
Self-preference biasA model judge rates outputs from the same model family higher, independent of qualityUse a judge model from a different family/vendor than the systems being compared
Simulating verbosity bias and position bias with a deterministic toy judge
def toy_judge_score(text, position_bonus, self_pref_bonus=0.0): """Deterministic stand-in for the surface cues studies show under-specified LLM judges latch onto: raw length, which slot ('first') the answer was shown in, and a small bonus if the answer 'sounds like' the judge model's own style. A real judge is not scripted like this -- this is a simulation of the documented FAILURE MODE, not a model of how judging should work.""" length_score = min(len(text.split()) / 40, 1.0) return 0.6 * length_score + position_bonus + self_pref_bonus # ---- 1. verbosity bias: same position, compare a short-correct vs long-wrong answer concise_correct = "Paris. It became the capital after the Capetian kings centralised power there." verbose_wrong = ("Well, this is actually a fairly interesting question with a long history " "worth walking through carefully before answering, because many people assume " "it is Lyon due to its size, but the historically accurate answer is Marseille.") sc = toy_judge_score(concise_correct, position_bonus=0.0) sw = toy_judge_score(verbose_wrong, position_bonus=0.0) print("Verbosity bias (both answers shown in the same slot):") print(f" concise + correct: score={sc:.3f} ({len(concise_correct.split())} words)") print(f" verbose + wrong: score={sw:.3f} ({len(verbose_wrong.split())} words)") print(f" judge prefers: {'verbose+wrong' if sw > sc else 'concise+correct'}\n") # ---- 2. position bias: two answers of EQUAL length and quality, only slot order changes answer_x = "Canberra is the capital of Australia, chosen in 1908 as a compromise." answer_y = "The capital of Australia is Canberra, picked in 1908 to settle a rivalry." x_first = toy_judge_score(answer_x, position_bonus=0.05) y_second = toy_judge_score(answer_y, position_bonus=0.0) print("Position bias, X shown first, Y shown second (nearly identical content/length):") print(f" X (slot 1): {x_first:.3f} Y (slot 2): {y_second:.3f} winner: {'X' if x_first>y_second else 'Y'}") y_first = toy_judge_score(answer_y, position_bonus=0.05) x_second = toy_judge_score(answer_x, position_bonus=0.0) print("Same two answers, order SWAPPED (Y first, X second):") print(f" Y (slot 1): {y_first:.3f} X (slot 2): {x_second:.3f} winner: {'Y' if y_first>x_second else 'X'}") print("\nThe winner flips purely from which slot the answer landed in.")
Verbosity bias (both answers shown in the same slot): concise + correct: score=0.180 (12 words) verbose + wrong: score=0.540 (36 words) judge prefers: verbose+wrong Position bias, X shown first, Y shown second (nearly identical content/length): X (slot 1): 0.230 Y (slot 2): 0.195 winner: X Same two answers, order SWAPPED (Y first, X second): Y (slot 1): 0.245 X (slot 2): 0.180 winner: Y The winner flips purely from which slot the answer landed in.

toy_judge_score is a deliberately scripted stand-in, not a model of a real judge — but the two failure shapes it reproduces (a longer, wrong answer beating a short, correct one; a verdict that flips purely from slot order on two near-identical answers) are exactly the failure shapes reported for real LLM judges when the judge prompt does not explicitly control for length and position. Be honest about what this buys you: swapping order and averaging, or instructing against verbosity, REDUCE these biases, they do not eliminate them, and self-preference bias in particular has no clean automatic fix beyond judge diversity. LLM-as-judge is a useful, scalable SIGNAL — treat a judge score the way you would treat any other single metric in this chapter: informative, cross-checked against a second signal (a held-out human-rated sample, a second judge family, or a task-specific automatic metric), and never the only number that decides whether a system ships.

4.11 — Chapter Summary and What You Can Now Do

A cross-validated score answers "is this a fair test." Everything in this chapter answers the next question: "is the metric itself telling the truth." Calibration checks whether the model's confidence means anything. Imbalance-aware metrics and threshold-moving stop accuracy from hiding a model that does nothing useful. Slicing by subgroup finds the systematic failure an average erases. Controlled ablations separate a real effect from a lucky (or unlucky) data split. And once the system is an LLM or a RAG pipeline, the same discipline applies to a new set of axes: retrieval quality, faithfulness to retrieved evidence, hallucination, and the real, well-documented limits of using an LLM itself as the judge.

What you can now do
  • Compute a Brier score and a reliability table, and fix simple overconfidence with temperature scaling.
  • Explain why accuracy misleads on imbalanced data, and choose PR-AUC vs ROC-AUC, resampling vs class-weighting vs threshold-moving for a given scenario.
  • Slice any confusion matrix or metric by subgroup and recognize a systematic failure mode versus noise.
  • Tell a controlled ablation from an uncontrolled "just try it and see," and know why repetition across seeds matters.
  • Compute recall@k, MRR and nDCG for a retrieval result set, and know what each one does and doesn't reward.
  • Build a faithfulness heuristic, and explain concretely where lexical-overlap proxies for hallucination succeed and fail.
  • Name the three documented LLM-as-judge biases (position, verbosity, self-preference) and their mitigations, honestly stated as reductions, not fixes.
